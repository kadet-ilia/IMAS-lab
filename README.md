# Модельный эксперимент ИМАС — версия 3.2

Программный комплекс предназначен для воспроизводимого исследования доверительно-робастного коллективного принятия решений в интеллектуальной мультиагентной системе при наличии византийских агентов, Sybil-идентичностей и ограничений коммуникационной сети.

## Реализованные процессы

- генерация локальных предложений корректными и византийскими агентами;
- сценарии постоянного и малозаметного смещения, on-off-атаки и согласованного сговора;
- моделирование дополнительных Sybil-идентичностей с отложенной активацией;
- динамическая Beta-модель доверия с конечным окном наблюдения и забыванием;
- медианная агрегация свидетельств и регуляризованная глобальная репутация EigenTrust;
- временная изоляция агентов с порогом, подтверждениями и периодом охлаждения;
- арифметическое, доверительно-взвешенное и византийски-робастное агрегирование;
- ограничение выбросов, симметричное усечение и проекция решения на безопасный интервал;
- полносвязная, кольцевая, случайная и small-world-топологии;
- потери и задержки сообщений, ограничение пропускной способности, устаревание данных и временное разделение сети;
- один прогон, серии Монте-Карло, однофакторный и многофакторный анализ чувствительности;
- параллельное выполнение независимых прогонов;
- управление заданиями, отображение прогресса и расчет оставшегося времени;
- остановка серии с сохранением контрольной точки и продолжение расчета;
- кэширование завершенных серий по SHA-256 хешу канонической конфигурации;
- экспорт CSV/JSON и графиков SVG.

## Статистические области по прогонам

Для каждого шага сохраняются робастные решения независимых прогонов. По совокупности из `R` траекторий рассчитываются:

- среднее и выборочное стандартное отклонение с делителем `R−1`;
- области `mean ± 1s` и `mean ± 2s`;
- медиана и квантили `P5`, `P25`, `P75`, `P95`;
- эмпирические области `P25–P75` и `P5–P95`;
- область допустимого отклонения `x*(t) ± δ`.

Квантильные области не предполагают нормальности распределения и предпочтительны при асимметрии, мультимодальности и переключении режимов изоляции.

## Статистическое сравнение методов

Для RMSE, MAE, вероятности правильного решения и ошибки консенсуса выполняется парный percentile-bootstrap. Общие индексы прогонов сохраняют парность сравниваемых методов. В интерфейсе отображаются:

- средний эффект робастного метода относительно базового;
- 95%-й bootstrap-интервал;
- вероятность положительного эффекта;
- формализованный вывод о наличии или отсутствии подтвержденного преимущества.

Для метрик формируются гистограммы и диаграммы размаха со значениями `min`, `P5`, `P25`, медиана, `P75`, `P95`, `max`.

## Анализ чувствительности

Поддерживаются два режима:

1. Однофакторный анализ изменения доли византийских агентов.
2. Двухуровневый многофакторный план для параметров атаки, доверия, изоляции, шума и сети.

Для многофакторного плана рассчитываются главные эффекты, парные взаимодействия и таблица экспериментальных точек. Число точек и прогонов на точку задается пользователем.

## Сетевая модель и Sybil-атака

При включении сетевого режима предложения и свидетельства доступны только в пределах связных компонент. Модель учитывает:

- выбранную топологию и вероятность формирования ребра;
- случайные потери сообщений;
- целочисленные задержки доставки;
- максимальную допустимую давность последнего полученного значения;
- общий лимит доставляемых сообщений за шаг;
- временное разделение сети на сегменты;
- дополнительные идентичности, согласованно управляемые нарушителем.

На графике сетевой диагностики отображаются размер крупнейшей компоненты, число доступных предложений и доля доставки сообщений.

## Графическая оболочка

Интерфейс React содержит вкладки:

- «Один прогон»;
- «Монте-Карло»;
- «Чувствительность»;
- «Данные»;
- «Справка».

Вкладка «Справка» включает постановку задачи, модель агентов и нарушителя, модель сети, доверие, репутацию, изоляцию, методы агрегирования, межпрогонную статистику, bootstrap, чувствительность, архитектуру программного комплекса, порядок эксперимента, правила интерпретации и ограничения применимости.

## Требования

- Python 3.11–3.13;
- Node.js 20.19 или новее для запуска приложения; Node.js 22.17 или новее для встроенной браузерной проверки;
- 4 Гбайт оперативной памяти для базовых серий; объем зависит от числа агентов, шагов и прогонов;
- разрешение экрана от 1120 пикселей по ширине.

## Запуск в Windows

Рекомендуемый способ — выполнить `start_gui.bat` из корневого каталога проекта. Скрипт автоматически:

1. создаёт локальное окружение `.venv`;
2. устанавливает `numpy`, `pandas` и `matplotlib`;
3. проверяет фактически используемый интерпретатор;
4. устанавливает зависимости интерфейса;
5. собирает и запускает приложение.

После запуска открыть `http://127.0.0.1:4173`. Для установки только Python-зависимостей предусмотрен файл `install_dependencies.bat`.

Ручной запуск:

```powershell
py -3 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe check_environment.py
$env:PYTHON = (Resolve-Path .venv\Scripts\python.exe)
cd gui
npm ci
npm run build
npm start
```

Важно: команда `python gui_bridge.py` должна выполняться тем же интерпретатором, в который установлены зависимости. Не следует запускать мост системным Python после установки пакетов в другом виртуальном окружении.

## Запуск в Linux/macOS

Рекомендуемый способ:

```bash
chmod +x start_gui.sh
./start_gui.sh
```

Скрипт создаёт `.venv`, устанавливает зависимости Python и Node.js, проверяет окружение и запускает сервер.

## Пакетный запуск без GUI

```bash
python experiment.py --config config.json --output results --sensitivity
```

## Тестирование

```bash
python -m unittest -v
cd gui
npm ci
npm run build
npm run verify
```

`npm run verify` выполняет краткую браузерную проверку загрузки панели, наличия новых сетевых и статистических параметров, вкладки «Справка» и отсутствия ошибок JavaScript.

## Структура

- `experiment.py` — математическое ядро, сеть, Sybil-модель, статистика, параллельные серии и чувствительность;
- `gui_bridge.py` — JSON-мост и сообщения о прогрессе;
- `config.json` — полная конфигурация пакетного запуска;
- `gui/server.mjs` — локальный сервер, менеджер заданий, остановка, контрольные точки и кэш;
- `gui/src/main.jsx` — интерфейс, графики, статистические панели и справка;
- `gui/src/styles.css` — стили интерфейса;
- `test_experiment.py` — модульные тесты;
- `runs/` — автоматически сохраняемые журналы запусков;
- `cache/` — кэш и контрольные точки;
- `results/` — результаты пакетного запуска.

## Методические ограничения

Комплекс воспроизводит синтетический модельный эксперимент. Он не подтверждает эксплуатационную эффективность ИМАС на конкретном объекте информационной инфраструктуры. Сетевая модель является дискретной и агрегированной: она не воспроизводит конкретные протоколы маршрутизации, пакетные очереди каждого канала и криптографические затраты. Для прикладной верификации требуется калибровка на цифровом двойнике или стенде, определение предметного безопасного множества решений и измерение задержек, сетевого трафика, загрузки CPU и памяти на целевой платформе.

## Исправление версии 3.1

Устранена ошибка `ModuleNotFoundError: No module named 'numpy'`, возникавшая потому, что прежний `start_gui.bat` устанавливал только зависимости Node.js и сервер запускал системный Python. Версия 3.1 использует локальное окружение `.venv`, автоматически устанавливает Python-зависимости и передаёт серверу абсолютный путь к правильному интерпретатору.


## Исправление версии 3.2: кодировки

Весь исходный проект хранится в UTF-8. Windows-скрипты `.bat` намеренно содержат только ASCII-символы и используют окончания строк CRLF, поэтому сообщения запуска не искажаются при любой локальной кодовой странице. Перед запуском Python устанавливаются `PYTHONUTF8=1`, `PYTHONIOENCODING=utf-8` и режим `-X utf8`.

Проверка проекта выполняется командой:

```bat
check_encoding.bat
```

или:

```powershell
.venv\Scripts\python.exe -X utf8 encoding_audit.py
```

CSV-файлы сохраняются в `UTF-8 with BOM` с разделителем `;` для корректного открытия в русской версии Microsoft Excel. JSON и исходные файлы сохраняются в стандартном UTF-8 без перекодирования.
