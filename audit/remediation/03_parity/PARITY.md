# Межъязыковая проверка UP-34: границы доказанных свойств

Общий набор исходных чисел: [primitive_vectors.json](primitive_vectors.json). Независимые тесты: `gui/src/primitiveParity.test.mjs` и `test_primitive_parity.py`; оба тестовых набора выполняются в GitHub Actions.

| Примитив | Проверяемое свойство |
| --- | --- |
| Discounted Beta posterior | Матричное обновление свидетельств с пропусками, prior, весом давности и асимметричными значениями |
| Weighted trimmed mean | Сортировка и симметричное усечение экстремальных значений, сохранение весов |
| Regularized EigenTrust | Фиксированная точка с демпфированием и исключением неактивной вершины |

Оба языка проверяются по одним **аналитическим численным эталонам** с указанным допуском `1e-9`. Это даёт основание говорить о согласовании **трёх детерминированных операций** на тестовом наборе, а не об эквивалентности всех программ.

Python-движок `experiment.py` и исправленный `trustEngine.js` содержат разные алгоритмы генерации случайных чисел и различающиеся допущения об изоляции, доставке и ряде метрик. **Запрещено делать вывод о совпадении всех траекторий либо средних показателей без отдельного сопоставления** при синхронизированных экзогенных событиях, общей спецификации состояний и правилах расчёта. Дальнейшие действия UP-34: независимые миниатюрные сценарии с фиксированным потоком случайных событий, межъязыковое сопоставление каждого такта и документирование разрешённых погрешностей.

Сопоставление JS/Python не является ни доказательством правильности самого механизма доверия, ни эмпирической проверкой реалистичности угроз.

## Расширенная независимая проверка UP-34 — 06.11.2026

**Проверяемая версия:** `trust-js-2.9.0-remediation`. Проверка состоит из двух независимых блоков и выполняется в обязательной задаче `existing-python` GitHub Actions. Для сравнения применяется `gui/src/up34Bridge.mjs`, считывающий JSON-векторы из stdin; он вызывает **реальные функции** исправленного ядра JS. Ожидаемые ответы вычисляются в `test_up34_deterministic.py` на Python **без импорта испытуемых JS-функций**.

Проверяются численные и структурные результаты, включая состояние очереди после каждого такта, повторное использование сообщений и баланс `attempted=delivered+lost+dropped+expired+pending`. Абсолютный и относительный допуск численного сравнения — `3×10⁻⁸`; точные целые величины, булевы статусы и состав структур также проверяются.

### Сквозная проверка E1 по архиву первичных событий (3 трассы × 17 тактов)

В `gui/src/up34Bridge.mjs` получаются первичные записи реального `simulateRun` при отключённых сетевых ограничениях. Затем **независимый Python-алгоритм** из `test_up34_deterministic.py` для каждого такта:
1. Восстанавливает активность агентов, в том числе активацию Sybil и повторное включение после cooldown.
2. Заново рассчитывает прямое Beta-доверие и EigenTrust, локальные и интегральные оценки репутации.
3. По исходным предложениям и весам рассчитывает все три способа агрегации (включая робастное усечение).
4. По архивным наблюдениям обновляет свидетельства, применяет изоляцию и проверяет время срабатывания.
5. Сопоставляет решения, матрицу состояний, репутацию, число активных и доступных агентов, события изоляции и основные итоговые показатели.

Проверены три варианта с различными зернами генератора: без изоляции, с агрессивной и с менее агрессивной изоляцией. Суммарно проверяется **51 последовательный такт**. Такой тест выявляет нарушения передачи результатов между математическими процедурами, но не проверяет корректность распределения случайных событий, поскольку сами исходные события генерирует JS.

### Принципиально несовместимые свойства старого Python-стенда

Тесты `test_legacy_divergences.py` **подтверждают расхождения**, а не требуют равенства:

| Проверяемое свойство | `experiment.py` (историческая модель) | `trustEngine.js` (исправленная модель) |
| --- | --- | --- |
| `random`, `p=0` | Всегда создаётся кольцевой остов | Пустой граф `G(N,0)`, кроме отдельно описанного Sybil-дополнения |
| Свидетельства вне сети | Матрица содержит конечные свидетельства от неактивных источников | Источники и получатели вне активного множества исключаются |
| Отсутствие доступных предложений | Может применяться прошлое решение как fallback | Регистрируется отказ (значения `null`) |
| Просроченные предложения в очереди | В старой реализации не исключаются из очереди по TTL до передачи | В текущей реализации просроченные элементы удаляются и учитываются в отдельном счётчике |
| Обнаружение нарушителя | В ранней версии используется время первой изоляции, включая предатаковую | Учитывается только постатаковая изоляция, время относительно старта атаки |

Таким образом, **объявлять полную эквивалентность исходной Python-программы и JS нельзя**. Для согласованных тестовых данных установлена согласованность проверенных детерминированных этапов **исправленной JS-редакции с новой независимой Python-референсной реализацией**.

### Воспроизведение и оставшиеся ограничения

При наличии Python 3.11+, Node.js 22+ и зависимостей основного Python-проекта:

```bash
python -m unittest -v test_primitive_parity test_up34_deterministic test_legacy_divergences
```

Остаются открытыми: синхронизация генераторов и весь полный стохастический прогон старого Python/JS, независимая проверка сетевой топологии с разделениями и Sybil, потактовое эталонное сравнение всей модели **при включённых** сетевых ограничениях, накопление и хранение полноразмерных первичных данных E2–E6, статистическая мощность и проверка внешних угроз. UP-34 **частично выполнен**, а не закрыт; независимая научная приёмка UP-36 остаётся обязательной.

## Дополнение UP-34, 06.11.2026: полная сетевая трассировка E1

`gui/src/trustEngine.js` (версия `trust-js-2.10.0-remediation`) записывает `kind="topology"` в начале исходного журнала (`schemaVersion=2`). Для каждого независимого запуска сохраняются исходные экзогенные ребра и группы разбиения сети. Python-тест `test_up34_network_trace.py` строит собственную матрицу смежности и компоненты связности, на основании которых:
- определяет множество получателей и доступность сообщений в каждом такте;
- независимо выполняет сортировку очереди по срокам, доставку, потери, задержку, просрочку и пропускную способность;
- пересчитывает свидетельства, Beta-доверие, локальную репутацию, EigenTrust и три правила агрегации;
- выполняет изоляцию, восстановление, расчёт выявления нарушителей и итоговых показателей;
- сверяет накопленный поканальный баланс и отображаемые покадровые значения.

**Пять независимых конфигураций по 19 тактов** охватывают ring, random (включая p=0), small_world, complete, Sybil-активацию, разделение сети, on-off, управление изоляцией, 100%-е потери, нулевую пропускную способность и устаревание сообщений. **95 последовательных тактов** E1 при работающей сети добавлены к ранее проверенным 51 такту без неё; всего **146 потактово реконструированных состояний**.

Отрицательные проверки из того же тестового файла намеренно изменяют записанное значение наблюдения, метку времени завершения передачи либо добавляют петлю графа. Независимая проверка обязана выявить повреждение.

**Строгое ограничение:** исходные ребра и результаты случайных испытаний предоставляются JS-моделью, а не генерируются независимо на Python. Проверяются условные математические переходы и расчёт метрик, **не проверяются** статистический закон выборки графов и корреляция случайных потоков. Исторический `experiment.py` продолжает отличаться от текущей постановки, поэтому UP-34 остаётся *частично выполненным*.


## Дополнение UP-34, 06.11.2026: независимый пересчёт архивов E2/E6

Тест `test_up34_research_raw.py` независимо реконструирует решения по сохранённым полным исходным данным (вместо сравнения только готовых сводных чисел). Мост `gui/src/up34Bridge.mjs` возвращает фактические первичные записи выполнения исправленного JS-ядра, а эталонные оценки Python вычисляет самостоятельно по исходным наблюдениям и графовым событиям.

- **E2 (68 независимых реализаций):** для каждого из четырёх сценариев и 17 прогонов Python восстанавливает наблюдения 11 агентов, вес по значению/возрасту, простое среднее, усечённое среднее и оценку с наблюдаемыми весами. Проверяются диагностическая oracle-оценка, покрытие, вероятность ошибки, правильного решения, условная точность и возраст наблюдений. Учитываются полностью отсутствующие сообщения (случай 100%-й потери).
- **E6 (76 независимых реализаций):** для каждого из четырёх уровней компрометации и 19 прогонов Python самостоятельно воспроизводит три такта распространения по сохранённым 3×9 случайным событиям и ориентированным рёбрам. Далее вычисляются веса, средние и усечённые оценки, доли правильных/ошибочных решений, отказов, среднее отклонение, риск и общий охват информационным воздействием.

**Итого 144 самостоятельных расчёта на исходных реализациях** поверх 146 потактовых реконструкций E1 и 174 ранее проверенных наборов математических примитивов. Для E2/E6 скрытые эталонные метки прочитываются только при оценке качества, а не при определении прикладных весов.

**Ограничения:** исходные стохастические реализации производятся в JavaScript и затем независимо обрабатываются на Python. Не проверяются законы генерации нормального шума, независимость случайных потоков, обоснованность распределений угроз и внешняя калибровка моделей. Проверка также не означает эквивалентность исторического Python-движка. UP-34 остаётся частично выполненным.
