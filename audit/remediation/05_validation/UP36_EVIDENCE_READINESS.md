# UP-36: машиночитаемая проверка готовности доказательной базы

Этот этап **не является подписанной научной приёмкой**. Назначение `scientific_release_gate.py` — обнаруживать отсутствующие, неидентифицированные, изменённые либо несогласованные документы и исключать присвоение статуса «научно принято» на основании одних автоматических тестов.

## Состав обязательных доказательств

1. Полный оригинальный реестр 55 замечаний (`originalDefectRegister`) — JSON с массивом `defects`, 55 **уникальных** исходных ID и их неизменёнными формулировками `verbatim`. Каждой позиции соответствует `status` (`resolved` либо `not_applicable`), `evidenceReference`, `reviewerReference` и, при `not_applicable`, обоснование `justification`. **Нельзя** заполнять недостающие 39 ID предположениями.
2. Независимые измерения (`externalCalibrationDataset`) и пересчитанный отчёт `validate_external_calibration.py` (`externalCalibrationReport`) с хешем исходных данных. Проверяются данные **пяти** вероятностных исследований E1/E2/E3/E5/E6. Пункты V5 и V8 остаются заблокированными до получения оригиналов.
3. Отдельный формальный эталон E4 (`independentFormalE4`), проверяющий описанный ограниченный класс сетей Петри.
4. Протоколы эксплуатационных испытаний (`operationalStress`): аварийное прекращение питания, исчерпание IndexedDB-квоты, целевое оборудование, конкуренция вкладок и длительные вычисления. Для каждой записи нужен протокол с SHA-256 и `passed: true`. Отчёт о штатном Chromium CI **не заменяет** испытания на реальном оборудовании.
5. Повторно сформированные публикационные результаты всех шести экспериментов (`publicationRecalculations`); для каждого файла указываются `studyId`, `candidateCommit` и SHA-256.
6. Как минимум два независимых экспертных заключения (`independentReviews`) с разными `reviewerId`/организациями, охватом всех шести исследований, декларацией независимости и ссылкой на подписанный документ. Подлинность квалификации, подписи и независимость рецензента **не подтверждаются автоматически**.

Файл `acceptance_manifest.template.json` содержит **незаполненный** пример структуры, а не фактические сведения об исследовании. Для каждого файла используется запись `{"path":"relative/path","sha256":"64-символьное значение SHA-256"}` относительно отдельно указанного каталога исходных доказательств. SHA-256 позволяет выявлять изменения файлов, но не доказывает, что сведения в них истинны.

## Команды независимой проверки

Протокол без внешних файлов создаётся с отметкой `blocked_missing_independent_evidence`:

```bash
python scientific_release_gate.py --output acceptance-readiness.json
```

После получения реальных доказательств:

```bash
python validate_external_calibration.py /absolute/evidence/data.json /absolute/evidence/calibration_report.json
python scientific_release_gate.py --manifest /absolute/evidence/acceptance_manifest.json --evidence-root /absolute/evidence --output acceptance-readiness.json --strict-evidence
```

`--strict-evidence` возвращает ненулевой код, если отсутствует хотя бы один из перечисленных файлов/метаданных. **Даже если все файлы формально присутствуют**, отчёт содержит `scientificAcceptance:false`, `externalSourceAndLabelsAuthenticated:false`, `independentSignaturesCryptographicallyAuthenticated:false` и статус `evidence_present_needs_independent_authentication`. После проверки подлинности данных и подписей внешняя организация оформляет самостоятельный акт. Этот акт нельзя заменить записью `passed:true` в JSON.

## Интеграция с CI

CI выполняет `test_scientific_release_gate.py` на **заведомо синтетических** векторах, затем формирует артефакт `imas-up36-acceptance-readiness`. Зелёный CI означает, что механизм выявления отсутствующих доказательств работает, **но не означает готовность V5–V8**.

### Отдельный контроль целостности IndexedDB

Для результатов E2–E6 используется `RESEARCH_STORAGE_SCHEMA=2`: каждое сохранённое состояние и итоговый результат сопровождаются SHA-256 от ключа конфигурации и содержимого. При чтении проверяются хеш, версия ядра, полная конфигурация, инварианты `metricPassport` и контракт статистических выводов. Прежний кэш версии 1 не смешивается с новой редакцией. Это защита от непреднамеренного повреждения/несогласованности; **она не является криптографической аутентификацией** против враждебного скрипта того же origin и не гарантирует сохранности после потери питания.

## Статус на 06.11.2026

Автоматически проверяемые численные модели и их трассировки реализованы в `0.13.0-rc.13`; для внешней экспертизы всё ещё отсутствуют реальные калибровочные измерения, исходные 39 идентификаторов второго аудита, подтверждения полного цикла испытаний целевого оборудования и подписанные экспертные заключения. Пока эти материалы не получены и не подтверждены независимо, **UP-36 должен оставаться открытым**.
