# Паспорта показателей вычислительных экспериментов IMAS-lab (UP-04)

Дата: 05.11.2026. Версия схемы: `metric-passport-1.0`.

## Структура машиночитаемого паспорта

Источник: `gui/src/metricPassport.js`. Для каждого из шести исследований создаётся набор словарей, содержащих `code` (имя в JSON/CSV), `title` (русское название), `unit` (единица), `formula` (реализованная численная операция), `denominator` (знаменатель и размер выборки), `missing` (смысл `null` или особого граничного значения), `source` (область данных) и `scope` (уровень агрегирования). Каждое выполненное исследование E2–E6 экспортирует версию паспорта, его строки и заключение `metricIntegrity`; режимы расчёта доверия (E1) включают аналогичные поля в итоговые файлы.

| Эксперимент | Ключевые показатели | Интерпретационный риск |
| --- | --- | --- |
| E1 «Расчёт доверия» | Доля правильных решений, покрытие, условная точность, RMSE, обнаружение, доставка, баланс сообщений, диагностическая полоса, стендовое время | Отказы не тождественны ошибочным оценкам; номинальная полоса не является CI робастного оценивателя |
| E2 «Автоматические решения» | Покрытие, правильные/ошибочные решения на всех опытах, точность среди выданных, возраст наблюдений | Возраст наблюдений не является end-to-end latency; при отсутствии принятых решений точность = `null` |
| E3 «Коллективное решение» | Вероятность опасного состояния, средняя и 95%-я доля поражения, парный эффект | Коэффициенты снижения вероятности — синтетические сценарии, не реализованный алгоритм защиты |
| E4 «Опасные состояния» | Статус EF, обработанные и зарегистрированные маркировки, политика изоляции | Неполный BFS не подтверждает недостижимость; приоритетная политика — идеализированный контроллер |
| E5 «Каскадные последствия» | Средний ущерб, дополнительный ущерб, ES95, опасное состояние, парный эффект | ES95 с малым эффективным хвостом нестабилен; ущерб не идентифицирован в реальных денежных единицах |
| E6 «Нарушение коллективного решения» | Частоты верного/ошибочного решения и отказа, модуль отклонения, условный риск, доля агентов под влиянием | Охват информационным воздействием — свойство сценария, а не заслуга алгоритма |

## Программная верификация

`auditResultMetrics` независимо проверяет арифметические инварианты: для E2 сумма долей правильных и ошибочных решений равна доле принятых, для E6 сумма частот верных, ошибочных и отказов равна единице и функция риска совпадает с ценой событий; для E3/E5 частота опасности согласована с числом исходов; для E5 дополнительный ущерб неотрицателен, ES95 не меньше математического ожидания; для E4 состояние BFS и количество зарегистрированных маркировок согласованы с заданными форматами; для E1 контролируются отказы, решение/покрытие и баланс сообщений.

Нарушение выявляемого инварианта останавливает выдачу результата с диагностикой; подмена пропущенных значений нулями не допускается. `metricIntegrity.valid=true` означает только прохождение **перечисленных арифметических проверок** и не свидетельствует о правильности механизма моделирования.

## Остаточные замечания

Паспорта созданы для **ключевых научных показателей**, но не для всех вспомогательных полей экспорта и всех событий: единый покадровый реестр событий с машинно-проверяемой связью «исходные события → показатель → график» ещё не завершён. Необходимо дополнить паспорта производными величинами и фиксировать математический способ агрегирования отдельно для каждой диаграммы. Пока UP-04 и UP-32 остаются частично устранёнными.
