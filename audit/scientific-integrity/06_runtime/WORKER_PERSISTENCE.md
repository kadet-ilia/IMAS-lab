# Надёжность браузерных вычислений и сохранения результатов (UP-35)

Дата: 06.11.2026. Версия приложения: `0.9.0-rc.9`.

## Границы системы

Модуль `gui/src/trustBrowserClient.js` исполняет модель доверия в выделенных Web Workers, не используя внешний вычислительный сервер. Каждая задача задаётся конфигурацией, версией математического ядра, индексом эксперимента и номером прогона. Кэшированный результат и контрольные точки находятся в IndexedDB того же origin. При отсутствии API IndexedDB (например, в Node-окружении) доступен только временный Map; его нельзя считать постоянным хранилищем.

## Исправление управления заданиями

Права на выполнение задания внутри вкладки резервируются до начала асинхронного чтения кэша. Дополнительно браузер использует **Web Locks API** с эксклюзивной блокировкой `imas-lab-test-trust-storage-exclusive-v1` на весь цикл запуска и очистки IndexedDB. Другая вкладка того же origin немедленно получает отказ, а не ожидает в очереди. Если Web Locks API недоступен в браузере, вычисления и очистка отклоняются, поскольку локальная блокировка не защищает данные от конкурирующей вкладки. В среде Node без DOM сохраняется локальный механизм для автоматизированных тестов. Для каждого Worker проверяются его идентификатор, принадлежность индекса заданному shard, отсутствие повторного результата и полнота переданных задач до принятия `finished`.

Результаты накопленных задач записываются как последовательность неизменяемых снимков; `checkpoint` и итоговые данные считаются сохранёнными только после события **`readwrite transaction.oncomplete`**. Ошибки открытия, блокирования или отмены IndexedDB теперь возвращаются как ошибки, а не заменяются молчаливо временным Map. Очистка локального кэша также выполняется только после успешной транзакции.

Контрольная точка имеет схему `TRUST_CHECKPOINT_SCHEMA=2` и хранит `modelVersion`, полный `cacheKey`, число задач и список уникальных результатов с индексами. При восстановлении проверяются идентичность модели и задания, границы/уникальность индексов и структура записи. Повреждённая или посторонняя контрольная точка отклоняется с диагностикой; ранее созданные неверсионированные контрольные точки **не используются и пересчитываются**, чтобы исключить бесконтрольное смешение результатов.

После штатного `stop` либо ошибки Worker сохраняются уже принятые результаты и на следующем запуске пересчитываются **только отсутствующие индексы**. Частичные результаты не объявляются полными. Отмена до появления первых результатов сообщает об отсутствии результата.

## Проведённые испытания

- Автоматизированные Node-тесты с заменяемым Worker проверяют эксклюзивный запуск, корректность shard, остановку, восстановление, ошибки Worker, раннее `finished`, одно-, четырёхпоточный и автоматический режимы; сравниваются одинаковые математические результаты.
- Негативные тесты заменяют IndexedDB неисправным интерфейсом: ошибка открытия и отмена подтверждения записи должны приводить к отказу, а не к ложному статусу сохранения.
- Настоящий браузер Chromium в CI выполняет четырёхгрупповой абляционный эксперимент, проверяет повторный запуск из кэша, повторный запуск **после полной перезагрузки страницы** и сравнивает экспортированный JSON для **1 и 4 настоящих Web Workers**. Дополнительный двухвкладочный тест удерживает эксклюзивную Web Lock в первой вкладке и проверяет отказ от запуска стенда во второй. После освобождения браузер снимает блокировку автоматически. В проверенном CI результаты научных полей совпали; счётчик использованных потоков равнялся 1 и 4 соответственно.

## Остающиеся ограничения

Данные проверки не демонстрируют гарантированного сохранения при внезапном обесточивании/аварийном закрытии браузера, отказе файловой системы после подтверждения транзакции и исчерпании квоты во время очень длинных сценариев. Web Locks гарантирует эксклюзивность **только между поддерживающими API добросовестными контекстами данного origin**; внешний код того же origin, не использующий блокировку, может всё ещё писать в IndexedDB. IndexedDB не является серверным долговременным хранилищем с независимым резервным копированием. В случае закрытия вкладки результаты после последнего подтверждённого checkpoint могут быть утрачены; систематическое стресс-тестирование длительных сценариев остаётся открытым.

Статус UP-35: **частично устранено и проверено в CI**; полной гарантийной готовности и независимого нагрузочного заключения нет.

## Дополнение 0.14.0-rc.14: целостность хранения исследовательских результатов E2–E6

`RESEARCH_STORAGE_SCHEMA=2`, база `imas-lab-research-checkpoints-v2`. Контрольная точка и окончательный результат сохраняются как `{schemaVersion,key,sha256,payload}`, где `sha256` — криптографический хеш UTF-8-сериализации `JSON.stringify({key,payload})`. Отсутствие WebCrypto, неверный ключ или хеш приводят к явному отказу. При чтении кэшированного итога **повторно выполняются** `auditResultMetrics` и `auditResearchInference`, сверяется вся конфигурация и версия математической модели. Флаг `metricIntegrity.valid` из хранилища не считается сам по себе достаточным.

Негативные тесты: изменения исходных наблюдений или агрегированных метрик, неверные хеш/ключ/версия, самостоятельное повторное упаковывание некорректного научного результата, отказ `readwrite` при записывании контрольной точки по причине `QuotaExceededError`. Незавершённая транзакция не учитывается как сохранённая; корректный последующий запуск пересчитывает утраченную стадию.

Модель угроз: SHA-256 обеспечивает обнаружение непреднамеренной порчи и неконсистентных записей, **не обеспечивает криптографической подлинности** по отношению к вредоносному коду того же origin, имеющему возможность переписать и данные, и их хеш. Не заменяет резервное копирование и аппаратные испытания внезапного обесточивания, ресурса накопителя и квот разных браузеров.
