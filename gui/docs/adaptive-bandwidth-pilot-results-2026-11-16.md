# E1-А: исследовательская проверка перераспределения общего бюджета сообщений

**Дата:** 16 ноября 2026 г.
**Статус:** синтетический факторный пилот, предназначенный для верификации механизма `decisionBandwidthPolicy="opportunistic"`. Он не доказывает оптимальность выбранного перераспределения ресурсов, устойчивость полной ИМАС или повышение точности при произвольной атаке.

**Источник:** `gui/scripts/adaptiveBandwidthPilot.mjs` и первичные `adaptive-scheduler-pilot.json/csv` из результатов GitHub Actions. Контрольный расчёт 16 конфигураций выполнен в workflow №43909612707; выполнение этого workflow было прервано на более позднем этапе после успешного завершения пилота из-за следующего изменения ветки. Итоговая CI-проверка должна оцениваться по отдельному завершённому запуску.

**Математическая постановка:** `adaptive-bandwidth-scheduling-model.md`.

## 1. Исследуемая гипотеза

Предложено двустороннее заимствование незанятых слотов общего модельного бюджета C между трафиком E1 (предложения, свидетельства) и передачами коллективного решения E1-А.

Сравниваются две политики:
- `static`: для маршрутизируемых решений неизменно резервируется ⌊fC⌋ сообщений за такт, а E1 получает C−⌊fC⌋;
- `opportunistic`: в начале такта сохраняется резерв только для ранее ожидавших, своевременно доставляемых и имеющих маршрут пакетов, а затем маршрутизатору разрешается использовать остаток бюджета после фактической передачи E1.

Точная формула и инварианты приведены в математическом паспорте. Динамическое перераспределение не использует апостериорную ошибку решения или истинные метки нарушителей.

## 2. Факторная структура

N=14 агентов, 3 византийских агента, T=28 шагов; K=3 симметричного усечения, R=3 прогона каждой конфигурации. Фиксирована доля первоначального резервирования f=0,30. Режим адаптивного коэффициента — `risk_aware`. Применена поведенческая модель свидетельств и синтетическая согласованная стратегия нарушителей.

Изменяемые факторы: полная или кольцевая исходная топология; отсутствие или наличие временного разделения; C=24 либо 64 сообщения/такт; политика `static` либо `opportunistic`. Итого 2×2×2×2=16 конфигураций с 3 реализациями: 48 прогонов, по 5 отдельных контуров доверия — 240 методоспецифических расчётов.

В пределах каждой пары при одинаковой топологии, разделении и C используются одинаковые seed и номера прогонов. Но при изменении распределения ресурса меняются фактически доставленные предложения, свидетельства, доверие и результаты изоляции: пары совпадают по исходному случайному ключу, **но не по полным реализованным траекториям**.

## 3. Результаты

| Показатель | Статическое резервирование | Двустороннее заимствование |
|---|---:|---:|
| Средняя доля использованного общего модельного ресурса | **92,86%** | **98,28%** |
| Доля агентов от полного N с актуальным доставленным решением | **49,59%** | **44,86%** |
| Средняя RMSE рискоориентированного оценивателя | **0,195691** | **0,195524** |

Средняя парная разность `RMSE(opportunistic)−RMSE(static)` по 8 наборам остальных факторов равна −0,00016666 (уменьшение RMSE нового варианта). При этом средняя парная разность доли агентов, имеющих актуальное решение, составила −0,04730017, то есть **уменьшение примерно на 4,73 процентного пункта**. Доля задействованного бюджета выросла примерно на **5,42 процентного пункта**.

Все восемь парных конфигураций показали рост использования ресурса при заимствующей политике, а также уменьшение доли доставленных актуальных решений. По RMSE имеются случаи улучшения и ухудшения, поэтому среднее изменение в −0,00017 следует считать малым и неуниверсальным.

Механизм результата следует из правила последовательной обработки: больше сообщений E1 может быть принято после освобождения избыточного предварительного резерва, однако это оставляет меньше доступных переходов для доставки коллективного решения. Поэтому увеличение пропускной нагрузки **не тождественно** повышению информационной доступности итогового решения.

## 4. Программная проверка

Пилот проверяет для каждого метода, каждого прогона и каждого такта:

  U_E(t)≤C−R(t),   U_E(t)+U_D(t)≤C.

Контроль адресных публикаций:

  N_attempt=N_delivered+N_lost+N_blocked+N_expired+N_pending.

В архиве фиксируются: C, предварительный и целевой резерв, число сообщений E1, число переходов решений, высвобожденные слоты для E1, дополнительные слоты, заимствованные решениями, остаточная свободная квота и доля агентов с актуальными ссылочными значениями.

Тесты отдельно проверяют: отсутствие изменения исходного поведения `static`, пределы C=1 и f=0/1, разделение и восстановление графа, отсутствие досрочной доставки, строгую воспроизводимость по seed, целочисленность квот и закон сохранения пакетов. Переключение политики в интерфейсе включено в реальную браузерную проверку с расчётом Web Worker и выгрузкой JSON.

## 5. Научные ограничения

1. Три повторения в каждой ячейке **недостаточны для подтверждения устойчивого превосходства по RMSE или статистически обоснованного оптимума ресурса**. Интервалы доверия и поправки на множественность для данного пилота не заявляются.
2. Двустороннее заимствование представляет собой последовательный алгоритм в дискретных тактах, а не физический совместный MAC-планировщик. Ресурс задан в сообщениях/шаг, без учёта размера сообщения и возможностей конкретных рёбер.
3. Приняты централизованное знание активного графа и централизованное формирование коллективного решения. Отдельные распределённые локальные решения пока рассматриваются лишь в диагностической исследовательской модели и не являются штатным контуром E1-А.
4. Положительная динамика использования ресурса не должна подменять показатель покрытия сети итоговым решением или эффективность решений по истинной ошибке.
5. Результаты зависят от конкретной синтетической угрозы, топологии, шума, расписания разделения и доли резерва; без дополнительной заранее фиксированной проверки перенос результатов на реальные системы необоснован.

## 6. Вывод

Разработанный механизм подтвердил на рассматриваемом синтетическом наборе способность **снижать потери общего модельного ресурса**, но не подтвердил одновременного улучшения доступности коллективного решения или практически значимого снижения RMSE.

Для следующего этапа обоснования рациональных параметров сети следует рассматривать минимум три независимых критерия: точность коллективного решения, актуальность его доставки конечным агентам и стоимость использования общего ресурса. Переход к полноценной распределённой ИМАС потребует моделирования локальных решений, физического трафика и формального анализа замкнутого состояния.
