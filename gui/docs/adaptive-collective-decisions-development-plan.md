## 1. Исходное состояние и обоснование

В исходном коде `gui/src/main.jsx` реализованы шесть самостоятельных экспериментов E1–E6; в E1 доступны режимы «Один прогон», «Монте-Карло», «Чувствительность», «Устойчивость и точность», «Данные». Четыре исходных оценивателя хранятся в `gui/src/trustMethods.js`: `arithmetic_mean`, `trust_weighted_mean`, `trimmed_unweighted`, `proposed_robust`. Их численные определения в `gui/src/trustEngine.js` должны оставаться неизменными в исторических исследованиях E1.

Исследовательская предпосылка: при выполненном ранее анализе 72 конфигураций комбинированное доверительно-усечённое среднее не показало универсального преимущества над невзвешенным усечённым средним: средние RMSE составили приблизительно 0,15146 и 0,15258; комбинированный метод выигрывал в 26 из 72 конфигураций. Сильные выигрыши в одних фазах сопровождались проигрышем при иных временных законах воздействия. Данные — предварительное модельное наблюдение, не независимая валидация нового метода.

Цель E1-А: разработать, реализовать и экспериментально проверить алгоритм адаптивного формирования коллективных решений, определяющий степень использования репутационных весов, параметры робастного усечения и доверие к свидетельствам по доступным на текущий такт данным, без знания истинной принадлежности агентов к нарушителям.

В меню выбора эксперимента остаются шесть действующих позиций, а в наборе режимов E1 появляется «Адаптивные решения». Внутри новой вкладки предусмотреть подрежимы:

## 3. Формальная математическая постановка

На такте t доступен набор предложений x(i,t), маска фактически доставленных предложений, наблюдаемая история свидетельств и репутация r(i,t), вычисленная до получения новых свидетельств текущего такта.

Базовый метод без доверия: yT(t) = mean по множеству K(t) сохранённых после усечения предложений. Базовый метод с доверием: yW(t) = сумма w(i,t)*x'(i,t) / сумма w(i,t) на том же K(t), если знаменатель положителен; при отсутствии предложения использовать явный отказ.

Предлагаемая адаптивная модель:
  yA(t) = Projection_S[(1-alpha(t))*yT(t) + alpha(t)*yW(t)],
  alpha(t) ∈ [0,1].
Параметры должны рассчитываться исключительно по наблюдаемым на момент t данным:
  w*(i,t) = clip(r(i,t)^gamma, w_min, w_max);
  N_eff(t) = [sum w*]^2 / sum [w*^2];
  D(t) = |yT(t)-yW(t)| / max(sigma_min, 1.4826*MAD(xK));
  alpha(t) = clip(C(t) * min(1, N_eff(t)/N_ref) * exp(-lambda_D*D(t)),0,1).
C(t) — оценка достоверности репутационных свидетельств, которую необходимо определить отдельно с учётом их давности, полноты доставки, зависимости источников и качества калибровки. Временная заглушка C=1 не допускается как научно обоснованная доверительная мера; использовать её можно лишь как явно помеченную абляцию.

Правило alpha является исследовательской гипотезой, а не заранее доказанным оптимальным алгоритмом. Реализовать семейство управлений alpha: `off` (alpha=0), `fixed`, `confidence_only`, `confidence_disagreement`. Основная версия выбирается на независимой обучающей серии и затем фиксируется.

Отдельные варианты робастного предварительного преобразования:
 A: воспроизведение исторического порядка «медианное ограничение -> сортировка -> усечение» (обязательный контроль);
 B: «сортировка исходных оценок -> усечение -> медианное ограничение оставшихся»;
 C: усечение с адаптивным числом k(t).
Варианты B/C — отдельные экспериментальные оцениватели, а не молчаливая правка прежнего `proposed_robust`. Тестировать перестановочную инвариантность при равных и ограниченных значениях.

Адаптивное k:
  k(t) = min(k_max(t), max(0, f_hat(t)+delta_f)),
  k_max(t) = floor((m(t)-m_min)/2),
где m(t) — число доступных предложений, m_min — минимальное число сохраняемых наблюдений. f_hat(t) — оценка подозрительных оценок по наблюдаемым признакам, НЕ истинное число византийских агентов. Ошибка f_hat и отказ при недостатке данных входят в эксперимент.

Аналитическая контрольная оценка: при достоверной верхней границе eps ошибки оставшихся честных предложений, границе D_bad для оставшихся атакующих предложений и доле их суммарного веса eta(t) возможна оценка
  |yW(t)-x*(t)| <= (1-eta(t))*eps + eta(t)*D_bad
до проекции, если истиное значение принадлежит допустимому выпуклому множеству. eta вычислять только в диагностике симулятора по истинным меткам. Не использовать eta, истину, метки нарушителей и будущие наблюдения для формирования alpha, k, w и решения.

Для корректности сравнений проекция в заданный диапазон должна быть одинаковой для всех сопоставляемых методов (при этом оригинальные сырые E1-средние сохранить как исторические контрольные ряды).

## 4. Корректировка модели свидетельств и стратегий атак

Не заменять существующий генератор E1 без обратной совместимости. Разработать в E1-А отдельный `evidenceModelVersion` и выбрать режим:
- `legacy` — побитовое воспроизведение текущих свидетельств E1;
- `behavior_linked` — свидетельства основаны на наблюдаемых фактах поведения, отклонениях, времени, доставке и шуме;
- `correlated_witnesses` — зависимые свидетельства и согласованные ложные рекомендации;
- `delayed_evidence` — задержанные и утраченные свидетельства.

Сохранить причинный порядок такта: старая история -> репутация -> генерация и доставка предложений -> решение -> новые свидетельства -> изменение доверия и изоляция. Текущие свидетельства нельзя использовать для оценки текущего решения, если протокол не определяет их более раннюю доставку.

Отделить форму временной активности от стратегии атаки. Оставить пять законов `constant/linear/exponential/parabolic/hyperbolic` и добавить профили длительности, перерывов, повторного включения и импульсов через расписание фаз. Тип атаки задаётся независимо: постоянное смещение, скрытое смещение, согласованная атака, on–off, reputation boosting, подделка свидетельств, Sybil и адаптивное поведение. Реальные реализации последних трёх требуется документировать, а не подменять простым умножением смещения на интенсивность.

Сетевой режим: сохранить и исследовать полный граф, потери, задержки, ограничения пропускной способности, разбиения на компоненты и изоляцию. Учитывать отсутствие решения как отдельное событие, не заменять его истиной.

## 5. Архитектура воспроизводимого сравнения

Перед изменением E1 разработать минимальную расширяемую точку доступа к входам агрегатора. Принцип: один поток экзогенных событий и одна история доверия/изоляции для всех сравниваемых методов в режиме `estimator_only`. Данные такта: доставленные значения, доступность, веса, временные метки, прошлые свидетельства, сведения о сети; **никаких истинных меток в пользовательской части алгоритма**.

Вариант реализации: необязательный observer/hook в `simulateRun()` после доставки предложений и до получения новых свидетельств; отключённый hook не должен изменять ни результат, ни расход случайных чисел, ни порядок событий старой модели. При необходимости вынести общий `step context` в чистую функцию, не копировать ядро симуляции для новой вкладки. Запретить независимое повторное разыгрывание атак между сравниваемыми оценивателями под видом парного опыта.

Второй режим `closed_loop` моделирует отдельные состояния доверия и изоляции для каждого сравниваемого метода; внешние события синхронизируются ключевыми подгенераторами. Статистику `estimator_only` и `closed_loop` не смешивать. Разница между этими режимами должна быть видимой в каждом графике и экспорте.

Параметры исследования E1-А хранить в отдельном объекте конфигурации и валидаторе. Версии источников, модели угроз, модели свидетельств, адаптивного агрегатора и протокола случайных событий записывать явно. Кэш E1-А отделить по пространству имён от кэша E1, включая version, полный config, seed, план, фазовый профиль и признак режима сравнения.

## 6. Требования к интерфейсу

Раздел «Адаптивные решения» наследует текущий визуальный стиль. Слева группы параметров: состав агентов; параметры базового доверия; адаптация alpha; усечение k и робастное ограничение; сценарий и временной профиль атаки; сеть и политика изоляции; план статистических прогонов.

Основные блоки результатов:
1. Временная диаграмма коллективного решения и эталона (эталон доступен лишь в исследовательском отображении).
2. Динамика alpha(t), k(t), N_eff(t), доверительного расхождения D(t), состава доступных агентов.
3. Сопоставление абсолютной ошибки базовых и новых методов с выделением атакующих фаз.
4. Сравнение RMSE, MAE, покрытия решений, P(correct), хвостовых квантилей ошибок.
5. Репутация честных/византийских агентов как *постфактум* диагностическая визуализация, без передачи истинных меток алгоритму.
6. Исходная серия парных разностей по прогонам, доверительные интервалы и пометка множественных проверок.
7. При включённом скалярном контуре: e, V=e², deltaV, точная граница ISS и частота пропусков.
8. Экспорт JSON/CSV с полной конфигурацией, траекториями и метаданными.

Для тяжёлых расчетов использовать Web Worker, прогресс, остановку, checkpoint, восстановление и локальный IndexedDB. В интерфейсе сообщать о частичности, несовместимых версиях и ограничениях научной интерпретации. Весь раздел должен корректно отображаться на мобильной и настольной ширине.

## 7. Корректировка исследования устойчивости

В E1-А реализовать две математически чётко разграниченные ступени:
I. `auxiliary_scalar` — сохранение существующей вспомогательной модели e[t+1]=(1-g)e[t]-g*(y[t]-x*) при принятом решении и e[t+1]=e[t] при отказе. Оценивать ISS при возмущениях, количество принятых тактов, время восстановления и отсутствие сходимости на неограниченных отказах. Не называть это доказательством устойчивости ИМАС.
II. `closed_loop_state` — новая явная динамика z[t+1]=F(z[t],a[t],xi[t]) с включением ошибок агентов, доверия, сетевого состояния и политики изоляции. Перед реализацией зафиксировать равновесие или инвариантное множество, пространство режимов, вид и смысл возмущений. Разработать кандидат V(z), затем отдельно доказать или экспериментально проверить достаточные условия. Никаких утверждений о доказанной устойчивости до строгого вывода.

Скалярные и полносистемные показатели хранить в разных пространствах и не помещать в одну колонку «устойчивость».

- Все методы получать из согласованных экзогенных событий; пары анализировать по прогонным разностям с CI и контролем множественных сравнений. Подтверждение преимущества фиксировать по заранее определённым первичным метрикам, не по лучшей постфактум выбранной диаграмме.

- Критерий: повторяемость архивов, согласование таблиц/графиков/экспортов, независимая проверка критических вычислений, новая математическая справка. При отсутствии подтверждённого преимущества метод маркировать «экспериментальный», а не «лучший».

(среднее `ΔRMSE=−0.074909`), но уступил `local_sensor`
(среднее `ΔRMSE=+0.813359`). Это демонстрирует,
что инвариантность безопасного множества и качество стабилизации
являются различными свойствами. Результат не является
статистически подтверждающим из-за `R=3` и отсутствия
внешней калибровки.

**Следующий исследовательский подплан:**
ввести достоверно моделируемые отказы собственных датчиков,
потерю их точности и неоднородность доверия; определить,
когда коллективная оценка действительно способна восстановить
наблюдаемость. Для таких режимов понадобится новый
математический паспорт со строгими условиями применимости
защитного барьера, который не должен молча использовать
недостоверное измерение с прежней малой погрешностью.
Далее — заранее зарегистрированный подтверждающий дизайн
с независимыми seed и явной оценкой рисков недоступности
доверенного измерения.

## Дополнение 17.11.2026 — этап 12: пропуски измерений и интервальная сертификация

Реализован отдельный эксперимент с аутентифицированными,
но пропадающими либо документированно деградирующими
измерениями. Защитный контур вместо скрытой истины получает
причинную интервальную область допустимых состояний.
Сохранён контрольный режим `nominal`; новые сценарии opt-in.

Формулы и доказательство условной инвариантности зафиксированы в
`gui/docs/adaptive-local-sensor-fault-model.md`. Переход в
`certification_lost` регистрируется отдельно от физического
выхода за пределы безопасного множества. Преждевременная
остановка не считается успешно завершённым прогоном и не
оценивается по RMSE только выполненных тактов.

Запуск поискового исследования: `cd gui && npm run adaptive:local:sensor:pilot`.
Критерий завершения этапа: независимая межъязыковая проверка
интервальной модели, прохождение CI и фиксация области
неосуществимости гарантированного управления при длительном отказе.
Следующий исследовательский вопрос — условия, при которых
потенциально могут улучшать результат соседские измерения;
для вывода о гарантии необходима новая модель аутентификации,
общей наблюдаемой физической переменной и ошибок межагентных
измерений, а не декларация о доверии к соседскому консенсусу.

## Научные результаты поискового этапа 12 и дальнейшие направления

В синтетическом факторном плане `24 × R=3` из 72 прогонов
54 полностью завершены, а 18 прерваны при длительной утрате
собственного аутентифицированного измерения. Причина — рост
ширины интервальной области при `a=1.04` и `W>0` до
границы, за которой никакая единая ограниченная команда уже
не гарантирует `|x(t+1)|≤S`. Для всех трёх политик
обнаружен одинаковый такт утраты сертификата; это не
доказательство аварии на физическом объекте.

На поисковом критерии `λ=10` (штраф прерывания)
средние потери: `local_action:2.565360`,
`local_decision:2.590150`,
`local_sensor:2.522181`. Точность собственной измерительной
информации по-прежнему определяет лучший наблюдавшийся
вариант в выбранной модели независимых состояний.
Подробный протокол:
`gui/docs/adaptive-local-sensor-fault-pilot-results-2026-11-17.md`.

**Следующий этап 13:** построить физически и математически
обоснованную систему перекрёстных наблюдений собственного
состояния с помощью других агентов; описать задержки,
доверенность, ошибки и возможность получения сертификата
по межагентным измерениям при пропаже собственных.
Затем провести независимую подтверждающую серию,
не оптимизируя параметры на том же наборе seed.

## Дополнение 17.11.2026 — поисковая реализация этапа 13

Добавлен отдельный опциональный канал перекрёстных **физических** измерений состояния соседнего агента; его нельзя смешивать с обменом оценками. Источники аутентифицированы, пакеты доставляются причинно с потерями, задержкой и TTL, резервируют фиксированную долю той же пропускной способности. Для устойчивости к f злонамеренным источникам применяется интервальная оболочка множества значений с поддержкой m−f различных датчиков. Необходимы независимые измерительные приборы, публичная верхняя граница f и достоверный журнал фактических команд. При числе отправителей m≤f интервал не сужается. Научное описание: `gui/docs/adaptive-local-cross-sensor-model.md`; исследовательский пилот `npm run adaptive:local:cross:pilot`. Обобщение на реальную распределённую систему и независимая подтверждающая проверка пока не выполнены.
