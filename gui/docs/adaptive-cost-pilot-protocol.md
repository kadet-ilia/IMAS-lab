# E1-А. Этап М7: проверка вычислительной стоимости и сохранения исходного E1

**Версия протокола:** `e1a-cost-pilot-1.0.0`. **Статус:** аппаратно-зависимый диагностический микроэксперимент, не доказательство реального времени или производительности в эксплуатации.

## Постановка

Сравниваются четыре заранее зафиксированных способа формирования адаптивной оценки: `adaptive`, `risk_aware`, `regime_aware_discrete`, `regime_aware_blend`. Общие параметры: 30 агентов, 9 нарушителей, 48 тактов, фиксированное усечение k=6, синтетическая периодическая стратегия с P=10 и d=4, закон интенсивности constant, расписание sustained, `behavior_linked` свидетельства. Сетевые ограничения выключены.

Две отдельно отчётные рабочие нагрузки:
- `common_estimator` — общие для методов экзогенные предложения и история доверия.
- `closed_decision_feedback` — автономные для каждого метода контуры «решение → дальнейшие свидетельства → доверие»; здесь сравнение скоростей включает пятикратный расчёт E1.

Сохраняются исторические идентификаторы и формулы E1. При одинаковых seed и начальных условиях для сравниваемых политик исходные усечённое и комбинированное решения E1 должны точно совпадать по каждому шагу. Нарушение — остановка испытания.

## План, фиксированный до запуска

| Стадия | Прогревов для каждой пары «нагрузка–политика» | Измерений для каждой пары | Измеряемых полных прогонов |
|---|---:|---:|---:|
| smoke | 2 | 2 | 16 |
| reference | 3 | 16 | 128 |

Порядок запуска алгоритмов циклически меняется от повтора к повтору; это уменьшает, но не устраняет влияние прогрева V8, garbage collection и фонового планировщика виртуальной машины. Прогревные повторения не входят в численные результаты.

Измерения в одном Node.js-процессе на одном runner GitHub Actions с `process.cpuUsage` и `performance.now`:
- elapsed wall time [мс] за **целый** вызов `runAdaptiveSingle`;
- process CPU user+system time [мс] за вызов;
- изменение размера heapUsed до/после как **неустойчивая диагностическая** величина, не равная памяти алгоритма.

Отдельно публикуются среднее RMSE, медиана времени, 25-й и 75-й перцентили, модель CPU, архитектура, версии Node/V8, SHA исходников и неизменяемый дизайн. Полные прогонные значения сохраняются в CSV. Методы не подбираются по результатам по скорости.

### Критические ограничения

Измеряемое время включает **всю** эмуляцию E1, генератор событий, обработку свидетельств, вычисление выбранной политики и постобработку; выделить собственный вклад адаптивного коэффициента alpha только по этим временам невозможно. Процессное CPU время и длительность выполнения в виртуальной машине GitHub Actions нельзя механически переносить на другие процессоры, распределённую ИМАС, космические бортовые вычислители и реальные протоколы. Размер heap не является точной пиковой памятью алгоритма. Измерения не дают гарантии deadline и не устанавливают свойства безопасности.

## Верификация и файлы

1. `gui/src/adaptiveCostProtocol.js` — фиксированный исследовательский план.
2. `gui/scripts/adaptiveCostBenchmark.mjs` — последовательный прогон с циклической перестановкой порядка, запись hardware metadata и контрольных SHA.
3. `gui/scripts/auditCostBenchmark.py` — независимая сверка CSV, медиан, квартилей, исторического E1 и полноты показателей; не проверяет точность часов.
4. `tests/gui/adaptiveCostProtocol.test.mjs` — контроль плана и тождества E1 для всех политик в обоих режимах.
5. `.github/workflows/adaptive-e1a-cost-pilot.yml` — GitHub Actions smoke/reference.
6. `gui/cost-campaign-request.json` — запуск без изменения расчётных исходников.

Оригинальные научные отчёты М5 и прежняя проверочная выборка **не используются для настройки** этой серии. `regime_aware` остаётся экспериментальным и отключённым по умолчанию. Фактические результаты M7 должны оцениваться только после завершения CI и арифметического аудита архива.
