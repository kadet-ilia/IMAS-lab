# E1-А: научный протокол факторного исследования f × k × L

**Версия:** e1a-fkl-regime-factorial-1.0.0. **Дата фиксации:** 18.11.2026. **Ветка:** IMAS_Lab_test.

## Цель и математическая постановка

Исследуется зависимость ошибки скалярного коллективного решения от числа византийских агентов f, глубины симметричного усечения k и модельного запаздывания источника доверительных наблюдений L. Запаздывание относится к построению свидетельств и не моделирует транспортную задержку. Сетевая модель выключена, Sybil отсутствует.

Заранее фиксируются N=30, T=48, режим estimator_only, тип свидетельств lagged_observation, стратегия coordinated, постоянная интенсивность атаки на тактах 13–48. Параметры усечения k передаются и историческому E1, и оцениваемой E1-А. Адаптивное определение k отключено, чтобы не смешивать фактор k с другим управляющим алгоритмом.

Полный план:
- f ∈ {3, 6, 9, 12};
- k ∈ {0, 3, 6, 9, 12};
- L ∈ {0, 1, 2, 4};
- R=30 повторений для каждого из 80 сочетаний.

Четыре фиксированных режима: исходная adaptive, risk_aware, regime_aware с дискретным выбором и regime_aware с непрерывным смешиванием. В каждой паре одинаковы экзогенные события, предложения, доверие и исторические решения E1. Всего 2400 повторений по факторным ячейкам и 9600 вызовов симулятора. Повторения разных k и L намеренно используют один seed при одинаковых f и индексе прогона; эти ячейки нельзя считать статистически независимыми.

Основной контроль — исторический комбинированный proposed_robust E1, а не более слабый в некоторых сценариях trimmed_unweighted. Основная парная разность:

\[
D_s(f,k,L)=\operatorname{RMSE}_{s,\mathrm{regime\_discrete}}-
\operatorname{RMSE}_{s,\mathrm{proposed\_robust}}.
\]

Отрицательный знак означает выигрыш нового алгоритма. Для всех других режимов вычисляются аналогичные контрасты. Сохраняются полные прогонные метрики, фазовые ошибки, безусловная потеря со штрафом отказа, доля принятых решений, число переключений и диагностические трассы. Единица статистического анализа — **полный прогон**, а не отдельный такт. 95%-е доверительные интервалы по ячейкам являются описательными percentile-bootstrap-интервалами и не учитывают множественность 80 × 4 сравнений.

Для исследования влияния L при фиксированных f и k используется разность в разностях между наблюдаемым RMSE-эффектом при L и L=0:

\[
I_L(s;f,k,L)=D_s(f,k,L)-D_s(f,k,0).
\]

Аналогично при k и k=0. Такие сравнения выполняются при совпадающем индексе случайного прогона, но остаются условными результатами в пределах синтетической модели.

## Предварительно зафиксированная подтверждающая серия

До интерпретации поисковой серии механически выбраны 16 иных факторных сочетаний, R=100 и независимые от поисковой серии seed. Изменяются одновременно стратегия поведения (pulsed), временной закон интенсивности (hyperbolic) и расписание (double). Проверяется перенос эффекта на новый **совместный** класс воздействий, а не причинность каждого из этих трёх факторов в отдельности.

Для 16 контрастов дискретной политики с комбинированным E1 предусмотрен знак-перестановочный тест с коррекцией Холма при дополнительном допущении обменности знаков. Подтверждение запрещается использовать для перенастройки модели. Отдельные ячейки внутри f имеют общую последовательность исходных seed, поэтому нельзя объединять их как независимые наблюдения при оценке общего эффекта.

## Программные составляющие и аудит

- gui/src/adaptiveFklProtocol.js — конструирование и проверка неизменяемого экспериментального дизайна.
- gui/scripts/adaptiveFklCampaign.mjs — полные вычисления, SHA-256 исходников, атомарные контрольные точки и CSV/JSON.
- tests/gui/adaptiveFklCampaign.test.mjs — факторный план, совместимость, общие экзогенные реализации.
- .github/workflows/adaptive-e1a-fkl-factorial.yml — запуск и архивирование из ветки IMAS_Lab_test.
- gui/fkl-campaign-request.json — явный запуск выбранной стадии.
- gui/src/adaptiveFklResults.js и gui/src/AdaptiveFklResultsPanel.jsx — валидация и визуальная проверка импортированной сводки.

Запуск из каталога gui: npm run adaptive:fkl:design; затем npm run adaptive:fkl:smoke; затем npm run adaptive:fkl:exploratory. Для независимой подтверждающей стадии: npm run adaptive:fkl:confirmatory.

Браузерный просмотр доступен в разделе «Адаптивные решения» → «Факторная чувствительность f × k × L». Загрузить exploratory-summary.json из архива GitHub Actions. Локальная загрузка JSON и содержащиеся в нём контрольные суммы не обеспечивают криптографической аутентификации происхождения файла; необходимо сверять архив GitHub Actions.

## Критические ограничения

- Историческое распределение ошибок и размер эффекта новой политики на других классах атак **неизвестны** до завершения независимых испытаний.
- Изменение k одновременно влияет на исторический контроль и новый метод, поэтому необработанный RMSE нельзя автоматически интерпретировать как изолированный эффект новой политики.
- Не доказаны безопасность при произвольном сговоре, эффективность на реальных кибератаках, устойчивость полной ИМАС, свойства сети или достижение византийского консенсуса.
- Риск-ориентированная политика использует наблюдаемую медиану в качестве прокси прогнозного качества; сговор может искажать её. Свидетельства не имеют полевой калибровки.
- Нельзя утверждать критический порог k=f на основании только проверенных дискретных значений.
