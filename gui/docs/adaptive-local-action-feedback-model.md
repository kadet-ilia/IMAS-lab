# E1-А: ограниченный замкнутый контур локальных действий и безусловная оценка потерь

**Дата:** 17.11.2026. **Версии:** `e1a-local-directed-beta-shadow-1.2.0-action-feedback`,
`adaptive-study-2.3.0-local-action-loop-and-unconditional-loss`.
**Статус:** исследовательский опциональный режим, по умолчанию выключен.
**Ветвь разработки:** `IMAS_Lab_test`.

## 1. Предмет и границы модели

Различают (i) локальную оценку предлагаемого коллективного решения
`u_i(t)`, полученную из собственных наблюдений и реально доставленных
по одному ребру сообщений предыдущих тактов, (ii) ограниченное
**прикладное локальное действие** `z_i(t)`, (iii) диагностический
эталон `x^*`, известный **только после моделирования** для оценки
ошибки. Центральные E1-решения, глобальная репутация, изоляция
и свидетельства вычисляются независимо от `z_i(t)`.

Этот режим замыкает **внутреннюю цепь локальных состояний и соседских
сообщений**: принятое `z_i(t)` передаётся соседям в конце такта t,
а они могут использовать его **только после физической доставки**
на шаге t'>t. Он **не** моделирует обратную связь с физическим
объектом, работу всей системы защиты или византийский протокол.

## 2. Скалярные переходы

Пусть `[a,b]` — допустимый интервал локального действия, `γ∈[0,1]` —
коэффициент перехода, `δ>0` — максимальное изменение за один
соседний активный такт. При первом включении активного агента
`z_i(t−1)` инициализируется проекцией его текущего собственного
наблюдения `r_i(t)`; после потери активности состояние
сбрасывается во избежание повторного использования устаревшего
действия при последующем возвращении.

Если `u_i(t)` принято:

```text
z_i(t) = Π_[a,b] ( z_i(t−1) +
  sat_[−δ,δ] { γ [u_i(t) − z_i(t−1)] } ).
```

Если локальное решение отсутствует (`u_i(t)=null`), допускается
одна из двух **явных** политик:

```text
hold:     z_i(t) = z_i(t−1)
observe:  z_i(t) = Π_[a,b](r_i(t)).
```

Отказ не превращается в принятое локальное решение. Для
поддержания обмена при отказе наружу по-прежнему передаётся
собственное исходное предложение `r_i(t)`, а не сохранённое
неподтверждённое `z_i(t)`. При принятом решении отправляется
`z_i(t)` в рамках **того же** сетевого бюджета E1 и маршрутизируемых
решений, с задержками, вероятностями потерь, TTL и актуальными
физическими рёбрами.

Локальный блок доверия сравнивает приходящий пакет с сохранённым
**собственным сырым** `r_i(s)` на такте отправки s; актуальное
локальное действие не подменяет этот собственный опорный сигнал.
Невозможны непосредственное использование пакетов будущего такта,
экспериментальных меток нарушителя и эталонной истины.

## 3. Утверждение об ограниченности

Для любого активного агента с исходным наблюдением в `[a,b]`
индукцией по t получаем `z_i(t)∈[a,b]`. База следует
из явной проекции `r_i(t)`; переход при наличии решения
ограничен проекцией `Π_[a,b]`; переход при отказе оставляет
предыдущее допустимое значение или проецирует новое наблюдение.
В частности, на последовательных **активных тактах с принятым
решением** выполняется `|z_i(t)−z_i(t−1)|≤δ`.
Для политики `observe` при отказе, равно как и при возвращении
после инактивации, это ограничение межтактового изменения
**не утверждается**.

Ограниченность скалярного действия не означает сходимости
`z_i(t)` к `x^*`, внутренней устойчивости всего векторного
контура или безопасности применения реальных защитных средств.

## 4. Безусловная функция потерь

Для исследования фильтрации и отказов множество экспериментальных
единиц фиксируется **до** вычисления локального решения:

```text
H = {(i,t): i активен и честен по синтетической разметке на t}
L_λ(i,t) =
  (u_i(t)−x*)², если локальное решение u_i(t) принято;
  λ,             если u_i(t)=null.
R_λ = Σ_(i,t)∈H L_λ(i,t) / |H|.
```

Здесь `λ = localAutonomyRefusalPenalty` задаёт заранее известную
цену отказа в единицах квадрата ошибки. Это **постфактум функция
потерь**, а не оптимизируемый онлайн-функционал. Параметр λ не
передаётся в формирование `u_i`, доверия или управления `z_i`.
При пустом H метрика не определена (`null`).

Разложение, используемое в независимом контроле арифметики:

```text
R_λ = A + λ(1−C),
A = Σ_(i,t)∈H,принято (u_i(t)−x*)² / |H|,
C = |{(i,t)∈H : u_i(t) принято}| / |H|.
```

В отличие от условной RMSE по принятым выходам эта мера не
исключает такты отказа. Для сравнения двух политик P и Q,
проверяемых на сопоставимых множествах H и сценарных событиях:

```text
ΔR_λ = (A_Q−A_P) + λ(C_P−C_Q).
```

В пилоте отдельно оцениваются `λ∈{0;0,25;1;4}`, причём
пересчёт не требует повторного моделирования алгоритма.
Изменения R при варьировании λ **не являются** доказательством
эффективности какой-либо стратегии без обоснования фактической
цены отказа.

Дополнительная метрика `mean_local_autonomous_honest_action_mse`
считает ошибку реально **прикладного локального состояния z**
на всех честных активных тактах, включая удержание/сброс при
отказе. Она отличается от `R_λ` и не учитывает влияние действия
на реальный объект, поскольку такого объекта в данной модели нет.

## 5. Научный протокол и проверки

Тесты `tests/gui/adaptiveLocalActionFeedback.test.mjs`
проверяют (а) отсутствие алгоритмической зависимости от λ,
(б) точный расчёт R по записям всех агент-тактов, (в) детерминизм,
(г) причинную зависимость от доставленного ранее `z_i`,
(д) контроль ограничений при принятом решении, отказе и
повторной активации, (е) сохранность центральных траекторий E1
и баланса всех сетевых пакетов.

Исследовательский пилот
`npm run adaptive:local:action:pilot` охватывает
2 топологии × 2 режима разделения × 2 ёмкости ×
2 состояния локальной обратной связи = 16 ячеек,
по 3 реализации и 5 методам (240 метод-прогонов).
Всё ещё недостаточно данных для доверительных интервалов,
внешней калибровки и формулировок о превосходстве.

## 6. Следующий этап

Необходима отдельная **замкнутая модель физического/логического
объекта управления**, с формальным отображением
`s(t+1)=F(s(t),z(t),w(t))`, критериями безопасности,
явным резервным режимом и границами действий при потере
связности. Только затем можно изучать устойчивость всей ИМАС
и причинное влияние локальной защиты на реальные показатели.
