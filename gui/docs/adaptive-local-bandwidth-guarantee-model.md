# E1-А: контрольная базовая линия и спросо-ограниченная локальная квота

Дата фиксации: 16.11.2026. Объект сравнения: `IMAS_Lab_test`, исходный коммит
`65d999ab2488259e7c993b0a07af09607cc4e41b`. Новые изменения выполняются
в отдельной ветке, без модификации E1–E6, `IMAS_Lab` и `master`.

## 1. Статус и границы

Предыдущие режимы `static` и `opportunistic` сохраняются, значение по умолчанию
`static`. Новый режим `decisionBandwidthPolicy="local_floor"` допускается только
при `comparisonMode="network_routed"`, `localConsensusPilot=true` и
`localTransportEnabled=true`. Реализована гарантия **внутри одного модельного
такта** для достижимых соседских пакетов; это не утверждение об отсутствии
голодания при произвольной динамике или о реализации распределённого консенсуса.

## 2. Математическая постановка

Пусть общий лимит сообщений в такте t равен целому C, доля решений f_D,
доля локального транспорта f_L, где 0≤f_D,f_L≤1 и f_D+f_L≤1.
До выполнения транспорта E1 фиксируются:
- квота маршрутизируемых решений D=floor(C f_D);
- доступный локальный спрос q_L(t), равный числу ожидающих соседских пакетов
  с текущим активным ребром и достаточным остатком TTL;
- защищённая локальная квота L(t)=min(floor(C f_L),q_L(t));
- бюджет основного E1: C_E(t)=C-D-L(t).

Исходный E1 сначала обслуживает предложения и свидетельства, потребляя
U_E≤C_E. Затем маршрутизатор может передать не более D переходов U_D≤D.
Наконец, локальный транспорт получает оставшийся ресурс и передаёт U_L
пакетов. При корректном подсчёте спроса U_L≥L(t) и всегда:

```
0 ≤ U_E ≤ C − D − L(t)
0 ≤ U_D ≤ D
L(t) ≤ U_L ≤ C − U_E − U_D
U_E + U_D + U_L ≤ C
```

Если нет текущего локального спроса, L(t)=0 и неиспользуемая квота
возвращается E1 **до** его планирования. Если решений не хватает, остаточные
слоты также могут использоваться локальными пакетами **после** маршрутизатора;
обратная передача неиспользованных слотов в E1 после уже завершённого
планирования невозможна. Это последовательная модель в единицах
«сообщения/такт», не физический MAC-планировщик.

Свидетельства E1, маршрутизируемые решения и соседские сообщения учитываются
в разных пакетных регистрах, а общий бюджет — одним неравенством.
Неактивные или разорванные рёбра не создают спрос; фактическая доставка
проверяется на шаге прибытия; нарушители не передают алгоритму эталон x*.

## 3. Проверка и критерии приёмки

- `cd gui && npm test`: прежние регрессии и новый
  `adaptiveFairBandwidth.test.mjs`;
- `cd gui && npm run build`: совместимость браузерного интерфейса;
- экспериментальные результаты новой политики должны собираться отдельно,
  парными сериями со старой политикой на фиксированных внешних событиях;
- проверять замкнутый баланс адресных локальных сообщений и
  `U_E+U_D+U_L≤C` на каждом такте;
- проверять повторяемость при фиксированном seed и отсутствие изменения
  старых решений при неактивной политике.

**Неподтверждённые выводы:** улучшение точности решений, оптимальность
распределения ресурса, устойчивость против византийских участников,
глобальная сходимость или независимые распределённые состояния доверия.
Для таких выводов требуются дальнейшие эксперименты этапов 10–13.
