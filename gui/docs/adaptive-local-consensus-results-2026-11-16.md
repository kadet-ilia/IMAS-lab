**Алгоритм:** `gui/src/adaptiveLocalConsensus.js`.  
**Математическое описание:** `gui/docs/adaptive-local-consensus-model.md`.

## 1. Постановка исследования

В ранее реализованном E1-А централизованное коллективное решение формируется на основе фактически доступных сообщений. Дополнительная локальная модель, реализованная на следующем этапе, рассматривает динамический физический граф и допускает синхронные обмены состояниями только между непосредственными соседями. Она запускается **параллельно** существующему вычислителю и не изменяет эталонные методы E1, доверие, маршрутизацию, изоляцию и статистику самого E1-А.

Проверялась зависимость конечного разброса локальных оценок от количества условных раундов, исходной топологии и временного разделения сети. Введены N=12 агентов, из них 2 византийских, T=18 тактов, по две исходные реализации на конфигурацию. Обрабатывались два вида топологии (полный граф, кольцо), два режима разделения сети и R∈{0,2,5} локальных раундов. Фиксированы коэффициент обновления λ=0,75 и отсутствие дополнительного усечения в данном факторном пилоте (k_loc=0); алгоритм поддерживает k_loc>0 отдельно. Входные предложения и репутации брались из актуального модельного состояния E1. Синтетический нарушитель удерживал исходную изменённую оценку при локальных обменах.

План составляет 2×2×3=**12 конфигураций**, по 2 независимых прогона каждая, всего **24 имитационных прогона**. В каждом из них сохраняются пять исторических контуров E1-А; локальные значения вычисляются отдельно для каждого контура. Поэтому число полных методоспецифических расчётов составляет 120.

## 2. Определение исследуемого показателя

Для каждой действующей компоненты C и обозначаемого служебной синтетической разметкой множества честных агентов H вычислен диапазон локальных оценок после R раундов:

\[
D_C(t)=\max_{i\in C\cap H}z_i^{(R)}(t)-
\min_{i\in C\cap H}z_i^{(R)}(t).
\]

При наличии не менее одного честного агента в соответствующей компоненте максимальный внутрикoмпонентный разброс принят равным D_max(t)=max_C D_C(t). Данная метрика использует истинные метки нарушителей **только постфактум**, не на входе правила локального обновления.

Для нагрузки записывается число условных направленных сообщений за все раунды:

\[
M(t)=R\sum_{i\in V_t}\deg_{G_t}(i).
\]

Оно является **теоретическим счётчиком идеальных синхронных отправок**, а не фактически доставленными пакетами и не дополнительной нагрузкой на каналы E1. Отдельный транспорт локальных сообщений на данном этапе не реализован.

## 4. Интерпретация

При переходе от нуля к двум условным раундам в данном факторном плане средний разброс уменьшился с приблизительно 0,620 до 0,425. Однако пять раундов дали значение около 0,524. **Монотонное уменьшение разногласия при увеличении числа раундов в рассмотренном эксперименте не установлено.** По имеющимся данным нельзя однозначно отделить воздействие синтетического нарушителя, доверительного взвешивания, структурных свойств графа и конечного времени наблюдения.

При полном графе средний разброс оказался существенно меньше, чем при кольцевом, но обмен требовал значительно большего условного числа направленных сообщений. Нельзя заключать, что такой результат сохранится при общем ограниченном бюджете передачи: в настоящей локальной диагностике сообщения не расходуют реальную квоту E1 и не теряются.

В некоторых конфигурациях разброс растёт несмотря на увеличение R; следовательно, критерий «больше итераций — лучше» не может служить самостоятельным основанием для рекомендации параметров распределённой ИМАС.

## 5. Программная приёмка и ограничения

Регрессионные проверки отделили локальный расчёт от исходных алгоритмов E1. Проверены причинная локальность (данные одного агента за r раундов не могут пройти далее r рёбер), инвариантность к перестановке, изоляция данных между разъединёнными компонентами и сохранение всех локальных оценок внутри безопасного интервала. Отдельная интеграционная проверка сравнивает исходные траектории и детерминированные показатели E1-А при отключённом и включённом локальном диагностическом расчёте.

Запуск GitHub Actions `43911139081` завершился успешно: **279 из 279** модульных и регрессионных испытаний, производственная сборка, факторные пилоты и предыдущая сквозная проверка Chromium. Пользовательский сценарий включения новых локальных параметров в отдельный браузерный запуск проверяется дополнительно.

Выходные файлы: `gui/adaptive-results/adaptive-local-consensus-pilot.csv` и `gui/adaptive-results/adaptive-local-consensus-pilot.json`. Они включают факторные параметры, независимые реализации, по-тактовые состояния локальных оценок и информацию об идеализированных обменах. Полный архив сохраняется среди артефактов GitHub Actions с установленным сроком хранения.

## 6. Границы научного результата и дальнейшие этапы

Разработанная диагностическая модель даёт возможность изучать внутреннее согласование в отдельных компонентах графа, не заменяя централизованный E1-А. Вместе с тем **ещё не реализованы**: причинная доставка локальных сообщений через физические рёбра с задержками и потерями, включение трафика локального согласования в общий ресурс E1, полностью локальная репутация, асинхронное изменение топологии внутри обмена, произвольные византийские сообщения, независимые решения при разделении сети и математическое доказательство сходимости или вход-состояние устойчивости полной сетевой ИМАС.

Обоснованным следующим этапом является интеграция локальных раундовых сообщений с существующим маршрутизатором и единым планировщиком передачи. Только после этого появится возможность корректно оценивать влияние физических ограничений сети на точность и устойчивость локального формирования коллективных решений.
