**Дата:** 17.11.2026. **Ревизия расчётов:** `f5c89bdfa4e6d13a42d9154293d116fd234dd193`.
**Выполненный CI:** [E1-A 44015879393](https://github.com/kadet-ilia/IMAS-lab/actions/runs/44015879393).
**Независимая проверка:** [основной CI 44015879217](https://github.com/kadet-ilia/IMAS-lab/actions/runs/44015879217).

**Статус:** поисковая вычислительная серия, R=3; не результат

## 1. Структура исследования

Впервые в серии Е1-А рассмотрены изменяемые состоянием объекта
дальнейшие собственные измерения:
`x_i(t+1)=a x_i(t)+b u_i(t)+w_i(t)`.
Для выбора защищённого управляющего сигнала доступны три политики:
ограниченная история локальных действий (`local_action`),
текущее коллективное решение (`local_decision`) и прямое
управление по доверенному локальному датчику (`local_sensor`).
Последняя политика — самостоятельный контрольный вариант
в той же физической динамике и с теми же экзогенными
последовательностями, но **без использования**
соседской оценки для управления.

Проведены: две топологии (кольцевая/полносвязная) ×
два режима разделения × два бюджета сообщений за такт
(`C=8` и `C=32`) × три политики = **24 конфигурации**.
Каждая выполнена для **трёх** детерминированных
независимых реализаций; итого **72 прогона**.
Узлов 8, из них два генерируют скомпрометированную
передаваемую телеметрию; горизонт 24 такта.
Параметры объекта: `a=1.04`, `b=0.4`, `k=0.8`,
`S=2`, `U=1.2`, `W=0.04`, `V=0.04`;
номинальный коэффициент `q=|a−bk|=0.72`.
Априорные параметры удовлетворяют достаточным
условиям робастной инвариантности безопасного множества.

**Первичная описательная метрика** — RMSE физического
состояния после перехода на **всех честных
агент-тактах**, а не только на тактах с принятым
коллективным решением. В расчёт включены такты
отказа и применения барьерного управления. Это
устраняет селекцию наблюдений по доступности
коллективного решения, характерную для условной
RMSE предыдущих поисковых пилотов.

## 2. Результаты в парных конфигурациях

В таблице `Δ` есть среднее по трём парным
реализациям значение
`RMSE(local_action) − RMSE(контроль)`,
где меньшая RMSE соответствует меньшей средней
квадратической ошибке состояния. Разные виды RMSE
не смешиваются.

| Топология | Разделение | C | Δ против local_decision | Δ против local_sensor |
|---|---|---:|---:|---:|
| Кольцевая | Нет | 8 | −0,081960 | +1,184945 |
| Кольцевая | Нет | 32 | −0,163461 | +1,088697 |
| Кольцевая | Да | 8 | −0,092548 | +1,181813 |
| Кольцевая | Да | 32 | −0,134382 | +1,229368 |
| Полносвязная | Нет | 8 | −0,056291 | +0,891177 |
| Полносвязная | Нет | 32 | −0,010886 | +0,128193 |
| Полносвязная | Да | 8 | −0,044207 | +0,678784 |
| Полносвязная | Да | 32 | −0,015540 | +0,123892 |

Средние значения RMSE по восьми факторным условиям
(сначала среднее по трём реализациям каждой конфигурации,
затем равновесное усреднение конфигураций):

| Политика | RMSE состояния | Средняя конечная V=x² |
|---|---:|---:|
| Ограниченные локальные действия | **1,038678** | 2,179385 |
| Прямое локальное коллективное решение | 1,113588 | 2,286336 |
| Доверенный собственный датчик | **0,225320** | 0,001035 |

Для `local_action` средний контраст против
`local_decision` равен `−0.07490935`: наблюдается
меньшая RMSE во всех восьми условиях.
Но против `local_sensor` он равен `+0.81335877`:
**локальные коллективные режимы существенно уступают
прямому управлению по доверенному датчику** в
рассмотренных сценариях. Ни одна из восьми
факторных ячеек не показала преимущество
`local_action` над `local_sensor`.

Это отрицательный результат для гипотезы о
безусловной полезности соседских оценок в данной
физической модели. Он не опровергает их пользу
в иных режимах, например при недоступном
доверенном собственном датчике; такой случай
здесь **не исследован**.

## 3. Безопасность и различие механизмов

Во всех 72 прогонах выполнены программные и численные
проверки:

- `safetyViolations=0`: не обнаружено выхода
  за границу `|x|≤S`;
- `issViolations=0`: не обнаружено нарушения
  локального или рекурсивного сравнительного
  неравенства;
- бухгалтерский баланс и общий бюджет
  сетевых сообщений сохранены;
- одинаковые внешние шумы и одинаковые
  начальные состояния восстановлены по
  попарным seed;
- исходные траектории центрального E1
  не изменяются новым модулем.

Само по себе отсутствие нарушений на 72
траекториях не служит доказательством безопасности.
Основание заявленной **условной математической
гарантии инвариантности** — аналитический вывод
допустимого интервала управления из границ
погрешности измерения и возмущения
(см. [математическую модель](adaptive-local-plant-model.md)).
Численные и независимые Python-проверки контролируют
соответствие реализации указанным формулам.

В среднем частота вмешательства защитного барьера
при `local_action` составляла приблизительно
`0.064815` по всем честным агент-тактам,
при `local_decision` — `0.119213`,
при `local_sensor` — 0 в выбранном пилоте.
Стратегия собственного датчика существенно лучше
стабилизировала состояние, хотя не использовала
соседские оценки.

Отдельно фиксируется методологическое различие:
локальная коллективная оценка может быть
**доступной** и при использовании контроля
`local_sensor`, но управляющее средство
при этом её не применяет. Для устранения
неоднозначности добавлены раздельные поля
`honestCoverage` (доступность локальных оценок),
`honestLocalControlFraction` (фактическое
управление по локальной оценке) и
`honestFallbackFraction` (реальные
резервные переходы). Это изменение не касается
динамики объекта и первичной RMSE.

## 4. Методологические ограничения

Результаты получены для абстрактного скалярного
объекта и фиксированной модели угроз.
Доверенные собственные датчики существенно
точнее скомпрометированной соседской телеметрии;
поэтому сравнение является строгим для
названного сценария, но не
доказывает ненужность распределённого
управления вообще.

При нарушении доверия к самому датчику,
исполнительному фильтру, точности оценок
границ `V,W` или законности объекта
`F(x,u,w)` аналитическая гарантия
инвариантности перестаёт применяться.

В этой серии отсутствуют:
полномасштабная динамическая модель
реального защищаемого объекта,
эмпирическая калибровка распределений,
адаптивная атакующая политика,
киберфизические исполнительные задержки,
нелинейные ограничения,
доказательство византийского консенсуса,
формальная проверка сходимости
самого распределённого оценивателя.

**R=3** — недостаточный объём для
надёжной доверительной оценки и
выводов о статистической значимости.

## 5. Воспроизводимость и направления развития

```bash
cd gui
npm ci
npm test
npm run adaptive:local:plant:pilot
```

Архивы с полными индивидуальными данными
выгружаются в `gui/adaptive-results/` и
в экспериментальные артефакты CI:
`adaptive-local-plant-pilot.json`,
`adaptive-local-plant-pilot.csv`.
Независимый Python-оракул выполняется через
`python -m unittest discover -s tests/python -p "test_*.py" -v`.

Следующая задача — определить область, в которой
соседские оценки действительно необходимы,
например частичная недоступность/снижение точности
локальных датчиков, и сравнить политики по
заранее заданной общей функции потерь состояния
и ресурсов с **новым, не использованным при
подборе условий набором seed**.
Отдельно исследовать отказ самого исполнительного
барьера: при этом безопасная инвариантность
не должна бездоказательно сохраняться
в научных выводах.
