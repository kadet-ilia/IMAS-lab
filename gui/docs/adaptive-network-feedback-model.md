# E1-А. Компонентно-ограниченное распространение коллективного решения в сети

Версия канала: `e1a-decision-component-broadcast-1.0.0`.
Версия исследовательского режима: `network_feedback`.
Статус: **сокращённая модель сетевой обратной связи с явными ограничениями**.

Реализация: `gui/src/adaptiveDecisionChannel.js`, `gui/src/adaptiveScenario.js`, `gui/src/trustEngine.js` и `gui/src/adaptiveExperiment.js`.

## 1. Постановка

В базовой ИМАС для заданного момента времени t формируется динамический граф:
  G_t=(V_t,E_t),
где V_t — активные агенты, E_t — существующие рёбра базовой конфигурации графа с учётом временного разделения сети. Текущий алгоритм E1 вычисляет компоненты связности C_t(i) для каждого активного агента i. В режиме E1-А используется именно этот полученный базовой моделью результат, а не самостоятельная вымышленная топология.

Существенное архитектурное ограничение: глобальный коллективный оцениватель E1 **остаётся централизованным модельным вычислителем** и получает доставленные к нему предложения крупнейшей доступной компоненты базовой сетевой модели. Публикация готового решения моделируется *отдельным каналом* с назначенным источником o. Это не локальный алгоритм консенсуса каждой компоненты и не реализация маршрутизации конкретных пакетов вдоль последовательности рёбер графа.

## 2. Источник решения и момент передачи

Назначен агент o∈V — `decisionOriginAgent`. Передача решения, вычисленного на такте t, разрешена только если:
- источник o активен в G_t;
- его предложение действительно доступно вычислителю E1 (с учётом транспортных потерь/задержек);
- коллективное решение является конечной величиной (отказ от решения не образует пакет).

При выполнении условий формируются отдельные пакеты к каждому j∈C_t(o), включая адрес источника. Пакет содержит тройку (y_m(t),t,j). Индекс m задаёт соответствующий независимый агрегатор/контур доверия E1-А.

Отсутствие источника или его предложения регистрируется как `notDispatched`; отсутствие конечного решения — как `abstentions`. Получатели вне компоненты источника даже не рассматриваются как адресаты на данном шаге, поэтому не могут получать решение через разрыв сети.

## 3. Срок доставки, потери и актуальность

Параметры: задержка d∈{1,…,50} тактов, вероятность потери p∈[0,1], срок актуальности L∈{d,…,500} тактов.

Для каждой пары (t,j) из множества разрешённых адресатов разыгрывается независимое псевдослучайное событие U_{t,j}, полученное из фиксированного seed, индекса прогона, времени, отправителя и адресата. При U_{t,j}<p пакет относится к потерянным. Иначе помещается в очередь с временной отметкой прибытия t+d.

На такте τ=t+d выполняется повторная проверка:
  o∈V_τ, j∈V_τ, C_τ(o)=C_τ(j), τ−t≤L.
Если условие нарушено по сетевой связности/активности, пакет блокируется без возможности повторного «появления» после восстановления связности. Если нарушено условие старения, пакет удаляется как просроченный. Только при выполнении всех ограничений значение сохраняется у получателя j как последняя доставленная ссылка y_m(t).

Для свидетеля i и объекта j на шаге τ ссылка r_{i}(τ) признаётся доступной, если:
  C_τ(o)=C_τ(i)=C_τ(j), τ−t_i≤L,
где t_i — исходный такт последнего полученного свидетелем пакета. В противном случае используется нейтральное свидетельство 0,5. **Механизм никогда не использует решение текущего такта раньше его доставки на последующем такте.**

При восстановлении сетевой связности ранее успешно доставленная ссылка может вновь использоваться до истечения L, но пакеты, заблокированные при передаче, не восстанавливаются автоматически. Для одной цели разные свидетели могут располагать разными историческими версиями y_m(t).

## 4. Формирование доверительного свидетельства

Для конечного полученного значения r_i(τ) и доступного предложения x_j(τ):
  q_{ij}(τ)=[1+(|x_j(τ)−r_i(τ)|/δ)²]^{−1},
где δ>0 — фиксированный параметр согласованности. Затем добавляется шум наблюдения и, при наличии злонамеренного наблюдателя, синтетическая подмена его свидетельства по прежнему генератору E1-А. В случае недоступности предложения или ссылки, либо отсутствия достаточного числа доступных опорных наблюдений, используется 0,5.

Таким образом, свидетельство q_{ij} может различаться между свидетелями даже для одного объекта j. Неопределённое/нейтральное свидетельство не является подтверждением честности.

Скрытые истинные метки нарушителей используются только генератором синтетического поведения, но не на входе коллективного оценивателя. Значение x* используется лишь при последующей расчётной проверке точности.

## 5. Дискретная модель доступности

В каждом независимом контуре m агрегатор формирует y_m(τ), который публикуется и становится возможным источником свидетельств начиная с τ+d. Последующие доверие и изоляция вычисляются по собственным свидетельствам, и сеть на следующих шагах зависит от собственного множества активных агентов.

Состояние по методу m является частным вектором:
  z_m(τ)=(A_m(τ),H_m(τ),Q_m(τ),P_m(τ),R_m(τ)),
где A — активность агентов, H — окно матрицы свидетельств, Q — неотправленные/ожидающие пакеты решений, P — последние доставленные решения у агентов, R — вычисленные репутации. Указанный вектор описывает состояние имитационного алгоритма, **но ещё не является замкнутой аналитической моделью с доказательством устойчивости**.

Отдельная последовательность доступности:
  a_m(τ)=K_m(τ)/J_m(τ), J_m(τ)>0,
где K — число достижимых агентов, у которых имеется непросроченное решение на начало такта, J — размер текущей активной компоненты источника. При J=0 показатель не определён. Дополнительно сохраняются абсолютные количества K,J, очередь решений и диагностические счётчики.

## 6. Контроль баланса сетевых сообщений

Реализовано строгое равенство:

  N_attempt = N_delivered + N_lost + N_blocked + N_expired + N_pending.

Показатель считается отдельно для канала публикации решений и проверяется по каждому завершённому прогону E1-А. Порядок выполнения: формирование текущих компонентов → обработка ожидающих доставок → доставка предложений → вычисление текущего решения → постановка новых пакетов → обновление свидетельств/доверия → изоляция.

При моделировании **не утверждается**, что пакеты этого канала расходуют базовую полосу пропускания `bandwidth_messages_per_step`. Стандартный баланс предложений и свидетельств E1 не изменяется. Для исследования общей полосы нужен дополнительный межканальный планировщик доставки и учёт маршрутов.

## 7. Сопоставление с предыдущими режимами

- `estimator_only`: один контур доверия, сравнение агрегаторов, общее множество доступных наблюдений.
- `decision_feedback`: пять независимых контуров без сетевых ограничений; текущая оценка метода поступает в генератор свидетельств на том же такте, что соответствует идеализированной мгновенной обратной связи.
- `network_feedback`: пять независимых контуров при `network_enabled=true`; текущая оценка становится доступной только после ограниченной по компоненте сети доставки и установленной задержки. Недоставленное решение не влияет на свидетельства.

Режимы **не являются эквивалентными** постановками. Прямое вычитание их RMSE без фиксации и анализа условий наблюдаемости и транспорта не может изолировать эффект алгоритма агрегирования.

## 8. Неохваченные механизмы и план продолжения

Не реализованы: синхронизация реальных сетевых часов, очередь по каждому ребру, кратчайшие/альтернативные маршруты, изменения траектории пакета при промежуточных обрывах, подтверждения получения, повторная передача, криптографическая аутентификация решения, противодействие компрометации источника публикации, согласованный межканальный бюджет, независимое вычисление решения компонентами связности и полноценная теорема о многомерной устойчивости ИМАС.

Канал является **исследовательским приближением**, позволяющим корректнее оценивать доступность ссылочного коллективного решения, чем идеализация мгновенной общесетевой публикации. Он не является доказательством устойчивого сетевого консенсуса.
