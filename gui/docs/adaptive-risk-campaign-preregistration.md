# Предварительно зафиксированная программа проверки рискоориентированного алгоритма E1-А

Статус: программа численных испытаний **без подбора параметров по проверочной серии**. Не является протоколом слепой внешней валидации: предшествующие 3360 прогонов уже повлияли на концепцию нового способа адаптации.

Математическая модель: `adaptive-online-risk-model.md`.
Вычислительные файлы: `src/adaptiveRiskCampaign.js`, `scripts/adaptiveRiskCampaign.mjs`.
Протокол: `e1a-risk-ablation-1.0.0`.
Алгоритм прогностической невязки: `e1a-risk-prequential-1.0.0`.

## 1. Проверяемая гипотеза и контрольные условия

Основная гипотеза: причинный алгоритм управления доверительными весами `risk_aware` уменьшает среднюю ошибку коллективного решения по сравнению с исходным алгоритмом `adaptive` при одинаковых экзогенных событиях, репутациях и процедуре изоляции.

Для независимого прогона r в заранее указанной конфигурации c:

  Δ_{c,r}=RMSE_{risk,c,r}−RMSE_{adaptive,c,r}.

Отрицательное Δ означает выигрыш нового рискоориентированного алгоритма. Сравнение проводится только на уровне полного прогона, без трактовки коррелированных последовательных тактов как независимых наблюдений.

Вторичные контрольные контрасты: `risk_aware−trimmed_unweighted` и `risk_aware−proposed_robust`, отдельно доли принятых решений, интервалы и динамика α.

Заранее фиксированная граница практической значимости — |mean Δ|≥0,01. Отрицательные, положительные и близкие к нулю значения считаются равноправными результатами исследования.

## 2. Факторный состав

Приняты N=30, T=48, симметричное усечение k=6, отключённая транспортная сеть, отсутствие Sybil-идентичностей. Модель свидетельств используется исходная E1, в обеих ветвях идентичная.

Факторная матрица повторяет прежний *набор условий*, но использует другие независимые исходные seed: шесть временных профилей (постоянный, линейный, экспоненциальный, параболический, гиперболический, импульсный) × три расписания (одиночная, длительная, повторная атака) × четыре уровня f=3,6,9,12.

Основная серия — **72×30=2160 парных прогонов**, включающих **4320** независимых запусков вычислительного ядра E1-А.

Внутренняя проверочная серия — **12×100=1200 парных прогонов**, включающих **2400** запусков ядра, по заранее выбранным 12 конфигурациям. Для выбора этих 12 конфигураций использовалось детерминированное правило старого исследования, а не результаты новой рискоориентированной серии.

Всего при полном исполнении программы: **3360 парных сравнений**, 6720 запусков ядра E1-А. Программу smoke из трёх конфигураций × два прогона не включать в исследовательские результаты.

## 3. Изоляция случайности

Используются разные начальные ключи:
- основная серия: `seed=1300000000+4096·ordinal+317`;
- внутренняя проверочная серия: `seed=1900000000+4096·ordinal+317`;
- проверка исполнения: `seed=2070000000+4096·ordinal+317`.

Во всех случаях ordinal — фиксированный индекс конфигурации. Все seed находятся в диапазоне положительного 32-битного целого числа со знаком.

Для пары «новое α — старое α» одинаковы seed, run, сценарий, вектор поступивших предложений, репутации и результаты исторического алгоритма E1. Реализации `trimmed_unweighted`, `proposed_robust`, `adaptive_unweighted` и `adaptive_weighted` обязаны совпадать с машинной точностью на каждом такте. Если соответствие не выполнено, прогон отклоняется.

## 4. Фиксированные гиперпараметры

Контроллер `risk_aware` использует β=0,85; κ=5; n_min=4; ограничение нормированной невязки L=8; регуляризатор ε=0,05 и начальное смешивание p₀=0,5.

Невзвешенный и доверительно-взвешенный оцениватели и параметры усечения одинаковы в обоих режимах. Параметры не подстраиваются на основании фактических ошибок x−x* ни в ходе обучения, ни при сравнении.

Истинное значение x* используется исключительно при подсчёте прогонных RMSE после выдачи решения, а не в контроллере. В качестве суррогатной цели контроллер видит лишь медиану фактически доставленных сообщений следующего такта.

## 5. Статистическая обработка и научные ограничения

Для каждого заранее выбранного c вычисляются среднее парной разности, число улучшений/ухудшений, двустороннее sign-flip p-значение, описательный 95%-й percentile-bootstrap-интервал по полным прогонам. Для фиксированной семьи из 72 либо 12 конфигураций применяется поправка Холма. Стратифицированный bootstrap оценивает равновесное среднее эффекта по ячейкам, не объединяя отдельные временные отсчёты.

Применимость sign-flip зависит от обменности знаков парных ошибок при нулевой гипотезе. Общие seed не гарантируют эту предпосылку; получение малых p-значений не тождественно доказательству эффективности механизма или реальной информационной безопасности.

Новая 12-ячеечная серия является **проверкой на новых случайных реализациях уже рассмотренных классов условий**. Она не является внешней подтверждающей проверкой на принципиально новом объекте, независимых датчиках или реальных атаках. При выборе дальнейших параметров после ознакомления с итогами необходимо формировать ещё одну отдельную независимую проверку.

## 6. Архив, остановка и воспроизведение

Из каталога `gui`:
- `npm ci`;
- `npm run adaptive:risk:design`;
- `npm run adaptive:risk:smoke`;
- `npm run adaptive:risk:exploratory`;
- `npm run adaptive:risk:confirmatory`;
- `npm run adaptive:risk:all`.

Архив сохраняется по пути `gui/adaptive-results/risk/<fingerprint>`. Контрольная сумма fingerprint включает сам проектный протокол, фиксированные гиперпараметры и исходные тексты критических вычислительных модулей. По каждой конфигурации хранятся прогонные парные ошибки, четыре основных показателя качества, статистика, одна контрольная трасса обоих вариантов и сведения о seed. Не допускается незаметное смешивание результатов после изменения математического кода.

Главное ограничение: даже успешный результат нового алгоритма на данной серии будет свидетельствовать только о численной эффективности при зафиксированной синтетической постановке. Нельзя переносить его на сетевую ИМАС с неполной связностью и говорить о доказанной устойчивости замкнутой многомерной системы без независимого построения динамической модели.
