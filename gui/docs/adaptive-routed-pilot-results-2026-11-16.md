## 1. Экспериментальный план

Проверялась модель `network_routed` с пятью независимыми контурами доверия. Коллективное решение формировалось центральным вычислителем, далее передавалось адресно через последовательность рёбер действующего графа сети с вероятностными потерями, пересчётом маршрутов и заданным временем актуальности.

Фиксированы: N=16, f=4 византийских агента, T=30, k=3, R=3 исходных набора случайных событий на конфигурацию; статический сценарий, синтетическое согласованное отклонение предложений, поведенческая модель свидетельств, `alphaMode=risk_aware`. Вероятность потери обычных сообщений 0,02, сообщений коллективного решения на отдельном переходе — 0,05; длительность перехода — один такт, срок актуальности решения — шесть тактов.

Факторный план: две топологии (`complete`, `ring`) × два состояния разделения сети (нет, интервал 11–21) × два общих лимита C (30 и 90 сообщений/шаг) × две доли резерва β (0,15 и 0,40). Итого 16 конфигураций × 3 реализации = **48 прогонов**. В каждом прогоне отдельно рассчитано пять методов: **240 методоспецифических траекторий**. Начальные значения seed намеренно повторяются между подвариантами бюджета и резервирования одной и той же топологии/разделения для согласованных сравнений; следовательно, 48 прогонов не являются 48 независимыми между собой случайными факторными условиями.

## 2. Результаты расчёта доступности и сетевых ограничений

Доступность решения представлена как число активных агентов, имеющих непросроченное адресное решение к началу такта, **нормированное на полное число N**, а не только на число достижимых агентов. Результат 0 может соответствовать как отсутствию маршрута, так и задержке, изоляции, потере или недостатку выделенных сообщений.

| Фактор/режим | Средняя доступность решения от N |
|---|---:|
| Все 16 конфигураций | **46,95%** |
| Полносвязная исходная топология | 71,22% |
| Кольцевая исходная топология | 22,68% |
| Без временного разделения | 51,11% |
| С временным разделением | 42,79% |
| C=30 сообщений/шаг | 38,37% |
| C=90 сообщений/шаг | 55,53% |
| β=0,15 для решений | 38,72% |
| β=0,40 для решений | 55,18% |

Числа по уровням факторов являются описательными средними по восьми соответствующим ячейкам плана; округлены по построчным машинным сообщениям. Для этих значений не строились корректированные интервалы, и они не доказывают причинное действие указанных факторов за пределами принятой имитационной модели.

Ограничение общего бюджета было активным: средняя по конфигурациям доля реально занятых слотов исходных сообщений E1 и маршрутизируемых решений составила **92,18%**. Контроль каждый такт подтверждал, что суммарное количество запланированных передач не превышает заданный предел C.

## 3. Противоречие между доступностью и точностью

При увеличении доли статического резервирования решениям β с 0,15 до 0,40 доля агентов с актуальным доставленным результатом увеличилась примерно с **38,72 до 55,18%**. В то же время средний RMSE рискоориентированного агрегатора в тех же фиксированных факторных группах увеличился приблизительно с **0,20684 до 0,21064**.

Эти значения нельзя интерпретировать как статистически обоснованную монотонную закономерность: R=3, а уровни факторов рассчитаны на ограниченной синтетической совокупности. Тем не менее они указывают на необходимость **совместной многокритериальной оценки** распределения ресурса между предложениями/свидетельствами и передачей коллективного решения.

Средняя по 16 конфигурациям разность `RMSE(risk_aware)−RMSE(proposed_robust)` составила **+0,011761**. Следовательно, **в этой конфигурации синтетической сетевой модели адаптивный алгоритм уступил исходному комбинированному среднему по среднему RMSE**. Формировать утверждение о неизменном преимуществе адаптивного оценивателя при недостатке полосы передачи методологически недопустимо.

Сопоставление данного результата с прежними 3360-прогонными сериями не является прямым: изменены сетевая постановка, бюджет, доступность опорных сообщений, правило доставки и обратная связь доверия.

Дополнительно регрессионные тесты проверяют: запрет досрочного получения решения, многопереходную доставку по кратчайшим путям, поведение при распаде выбранного ребра, ожидание восстановления маршрута, отсутствие фиктивной передачи при полном исчерпании резервирования, стопроцентную потерю отдельных переходов, недоступность источника и воспроизводимость событий по seed.

Тот факт, что программа проходит тесты, доказывает согласованность описанных инвариантов с реализацией, **но не адекватность модели реальному распределённому объекту**.

## 5. Ограничения, существенные для научной публикации

1. Маршрутизация рассчитывается централизованно по полному текущему графу; не реализованы локальные неполные таблицы и служебные сообщения маршрутизации.
2. Коллективное решение изначально вычисляется единственным логическим узлом, поэтому алгоритм не решает задачу независимого локального консенсуса при разделённой сети.
3. Пропускная способность выражается в условных сообщениях/такт, а не в бит/с; не учтены различия размеров сообщения, физические скорости и задержки конкретных рёбер.
4. Статическое резервирование квот ресурса не является работосохраняющим, не предусматривает повторные передачи и не оптимизировано.
5. Используются синтетические генераторы свидетельств и атак, а не внешние калиброванные наблюдения.
6. Не представлено доказательства асимптотической, вход-состояние или иной устойчивости многомерной сетевой системы.

Поэтому наблюдаемые различия следует рассматривать как **обнаруженные эффекты математической имитационной модели**, достаточные для постановки следующего этапа исследований, но недостаточные для заявлений об универсальном улучшении ИМАС.

## 6. Направления дальнейшей реализации

Следующий технологический блок — переход от глобального вычислителя и кратчайшего пути при полном знании графа к локальным решениям агентов/компонент и распределённой маршрутизации, а также к единому работосохраняющему планировщику разных потоков сообщений с неоднородными физическими каналами. Отдельный теоретический блок — построение замкнутого вектора состояний «предложения–доверие–изоляция–маршрутизация–доставка» и формулирование проверяемых условий устойчивости.

Выполнение указанных блоков не следует смешивать с текущей успешной **программной** приёмкой исследовательской модели.
