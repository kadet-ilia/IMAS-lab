# E1-А: сравнительная аналитика полных прогонов, фаз и воспроизводимый экспорт (М6/М7)

**Дата:** 18.11.2026. **Статус:** программный модуль постобработки, независимый от управляющей логики E1/Е1-А. Этот модуль не создаёт новый алгоритм защиты, не меняет гиперпараметры или историю ранее опубликованных вычислительных исследований.

## Назначение

В разделе «Адаптивные решения» реализована дополнительная интерактивная панель «Сравнительный анализ полных прогонов и фаз» для:

- попарного сравнения `adaptive_robust` с **основным** `proposed_robust` и **дополнительным** `trimmed_unweighted`;
- анализа разности ошибки по **каждому целому прогону**, а не по зависимым временным тактам;
- раздельного рассмотрения активных и неактивных фаз воздействия на основании **фактической**, а не только номинальной интенсивности;
- сопоставления условного RMSE и безусловной потери с явным штрафом отказа;
- полной выгрузки результатов по всем прогонам и всем тактам диагностики;
- формирования воспроизводимого паспорта настроек, версии вычислительных компонентов, набора seed и порядка прогонов.

Реализация: `gui/src/adaptiveStudyDiagnostics.js`, `gui/src/AdaptiveStudyAnalyticsPanel.jsx`, `tests/gui/adaptiveStudyDiagnostics.test.mjs`. Панель подключена к `AdaptiveDecisionPanel.jsx`.

## 1. Методика парных оценок

Для каждого прогона `s` и выбранного контрольного оценивателя `b`:

[
D_s^{RMSE} = RMSE_{s,adaptive\_robust} - RMSE_{s,b},
quad
D_s^{loss} = L_{s,adaptive\_robust} - L_{s,b}.
]

Отрицательная разность соответствует меньшей ошибке/потере E1-А. **Единица анализа — полный прогон s.** При отсутствии принятых решений условный RMSE не определён (`null`), и подобная пара исключается из анализа условного RMSE с открытым учётом `nMissingPairs`. Безусловная потеря учитывает отказ заданным `decisionRefusalPenalty` на каждом такте и остаётся сравнимой, когда условная метрика отсутствует.

Средняя разность рассчитывается по полным конечным парным наблюдениям, а 95%-й интервал — нормальной аппроксимацией по выборочному стандартному отклонению **целых прогонов**. При `R=1` границы интервала отсутствуют. Это описательный интервал Монте-Карло по фиксированному плану: он не учитывает ошибку генератора угроз, зависимость конфигураций, множественные проверки или перенос на реальные атаки.

Для режима `estimator_only` различные оцениватели видят общий экзогенный поток. В режимах `decision_feedback` и сетевой обратной связи методы влияют на собственную историю доверия и доступности; **одинаковый seed не означает тождественный поток наблюдений в обратной связи**, и интерпретация различий относится к сравнению альтернативных замкнутых контуров.

## 2. Фазовые показатели

Для каждого метода и прогона такты классифицируются по уже записанному `attack_intensity`:
- `attack_active`, если эффективная интенсивность >0;
- `attack_inactive`, если эффективная интенсивность =0.

Для каждой подгруппы отдельно рассчитываются количество тактов, количество принятых решений, отказы, покрытие, RMSE и безусловная потеря. Разность фазовых RMSE формируется **по одному числу от каждого целого прогона**, а не по объединённым тактам всех прогонов. Прогоны без соответствующей фазы исключаются из её среднего с регистрацией `nRunsWithPhase`; значения не заменяются нулём.

Активность означает активный **модельный график кибервоздействия**, а не подтверждённую успешную доставку вредоносного сообщения. При независимых временном законе интенсивности и периодическом поведении атакующего возможны сценарии, где номинальная интенсивность ненулевая, а реально активных атакующих тактов ноль. Для выявления таких случаев рассчитываются `nominalActiveSteps`, `activeSteps` и `suppressedSteps`.

## 3. Независимый контроль арифметической согласованности

Перед отображением исследовательских данных проверяются:
1. Версия и структура полного исследования; номер и длина каждого прогона; полный состав **пяти** исторических идентификаторов методов.
2. Конечность эталона, эффективной интенсивности и числовых результатов; совпадение порядка тактов.
3. **Повторный расчёт** из записанной полной траектории для каждого метода: покрытия, числа отказов, условного RMSE и безусловной потери; несогласованность вызывает ошибку, а не молчаливое усреднение.
4. Наличие и диапазоны парных данных; исключение неопределённого условного RMSE без изменения безусловной оценки.
5. Безопасное плоское сериализованное представление CSV и защита строковых полей от Excel/CSV-инъекции формулами.

Это проверка арифметики записи/постобработки на тех же исходных данных; она не является независимым доказательством истинности модели или достаточности показателей для реальной информационной безопасности.

## 4. Форматы экспорта

| Формат | Состав |
|---|---|
| `imas-e1a-paired-runs-*.csv` | Одна строка на полный прогон, RMSE и безусловная потеря обоих методов, парные разности, покрытие, отказы, активные/подавленные такты, переключения |
| `imas-e1a-phase-metrics.csv` | Каждый прогон × каждый из пяти методов × активная/неактивная фаза; показатель отсутствует, если фазы в прогоне нет |
| `imas-e1a-all-run-policy-events.csv` | Все такты всех прогонов: выбор оценивателя, наблюдаемое состояние режима, веса, `alpha`, `k`, качество свидетельств, переключения |
| `imas-e1a-reproduction-manifest.json` | Версии методов, конфигурация, seed, сценарий, расписание фаз, число и идентификаторы прогонов, штраф отказа, название основного контроля и предупреждения |
| Прежний полный JSON | Сохраняется без изменений; включает исходные подробные траектории и диагностические состояния |

**Ограничение происхождения:** браузерная сводка содержит версии моделей и исходные параметры, но не аутентифицирует бинарный результат, не подтверждает Git commit и не включает проверенный криптографический хеш всех исходников. Для публикации результаты следует воспроизводить на зафиксированном коммите и сверять с исходным архивом GitHub Actions.

## 5. Условия приёмки

- Исходные алгоритмы E1 и E1-А **не модифицированы**; обработка результатов выполняется только после окончания прогона.
- Вычисленные из траекторий метрики совпадают с сохранёнными в `run.metrics` до численной точности; отказы не исчезают из безусловной потери.
- Отсутствие активных фаз не порождает фиктивную нулевую фазовую ошибку.
- Основной контроль остаётся `proposed_robust`; переключение контроля в интерфейсе не меняет результат симулятора.
- Все независимые прогоны экспортируются, а не только первая траектория; конфигурация и научные ограничения явно записаны.
- Результаты нового режима `regime_aware` не объявляются превосходящими E1 до независимого подтверждения; v2 требует иной обучающей и подтверждающей серий.

**Далее по плану:** М7 — замеры вычислительной стоимости на фиксированной аппаратной среде, проверка инвариантов в режимах обратной связи и строго отдельный новый исследовательский протокол для будущего `regime_aware v2`. Реальная сетевая/космическая обстановка остаётся вне подтверждённых результатов скалярного эксперимента.
