# E2 — Автоматические решения

Автор стенда: Ушаков И.А. Название соответствует окончательной статье от 26.11.2026.

## Запуск

Из корня репозитория, Node.js 22 (Python для обычного запуска не требуется):

```bash
cd gui
npm ci
npm run dev
```

Для статической сборки: `npm run build`. Сборка проверяет обязательные статические ресурсы `gui/public/e2-fixtures.json` и `e2-fixtures.sha256`. Они входят в поставку; отсутствие или несовпадение хеша останавливает сборку. Python нужен только для регенерации и независимой проверки. Импорт JSON через настройки является резервным способом. Файл генерируется из исходных частот, независимых валидационных выборок и контрольных входов, а не из опубликованных итоговых таблиц. В режиме статьи параметры заблокированы.

## Независимая численная проверка (Python 3.13)

```bash
python -m pip install -r research/automatic-decisions/reference/requirements.txt
python research/automatic-decisions/reference/experiment.py
python research/automatic-decisions/reference/extra_checks.py
cd gui
npm run e2:fixtures
npm run test
npm run e2:parity
npm run build
```

Скрипт parity сравнивает по каждой калибровке все девять наборов выходных данных с Python (4874 записи, включая 32 парных контраста). Допуск 1e-8. Для S4/S7/S8 номинальные границы не являются гарантией для тестового закона. M10 — идеализированный эталон. Пользовательский режим использует отдельный Xorshift32 и не обязан давать те же численные результаты, что NumPy. LP в пользовательском режиме не выполняется; в режиме статьи проверяются оптимумы независимого LP из эталонного файла. Предельное число конфигураций 300000 — предварительное инженерное ограничение, не измеренный предел производительности.

Рабочая страница использует отдельное ядро `gui/src/automaticDecisions/`, Web Worker и версионированное IndexedDB. Предыдущая функция `runUncertainty` сохранена для исторических тестов, не вызывается новым интерфейсом. Остальные исследования не заменены. Применимость к реальным объектам не подтверждена.

## Развитие E2.1

План: [E2_ROADMAP.md](E2_ROADMAP.md). В подразделе «Общее» сохранены все серии статьи. Самостоятельный подраздел «Монте-Карло» сравнивает M6/M7 при фиксированной синтетической калибровке; доступен выбор сценария S1–S8, двух зерен, размера выборки и точного сравнения. Все восемь подразделов доступны. При смене режима неактивная страница размонтируется; общие, MC и расширенные серии сохраняют контрольные точки в IndexedDB. Повторный запуск с теми же параметрами восстанавливает серию. Пользовательский импорт не сохраняется автоматически.

## Расширенные исследования E2.2–E2.8

См. [E2_METHODS.md](E2_METHODS.md) и [E2_ROADMAP.md](E2_ROADMAP.md). В каждой панели имеется самостоятельный запуск и экспорт. Внешние данные обрабатываются локально. Никакие результаты синтетических серий не являются эксплуатационным подтверждением.

## E2.9–E2.12

В «Монте-Карло» доступна кнопка расширенного режима с произвольным составом групп, повторными калибровками, досрочной остановкой и выборкой по значимости. В «Данные» флаг автоматического выявления групп разделяет обучение на выявление и последующую калибровку. В «Оптимизация» добавлен ввод JSON неоднородных кандидатов и консервативная имитационная оценка больших пространств. Методика: [E2_METHODS.md](E2_METHODS.md). Независимая численная проверка: из gui выполнить node scripts/check-e2-extended.mjs после установки Python-зависимостей.

## E2.13–E2.16

В «Динамика» доступны взвешенная адаптивная калибровка и оптимальная остановка с активным запросом группы. Для взвешенного режима используется L1; задайте длинное и короткое окна, забывание и повторы. В оптимальном режиме задайте бюджет запросов, цену запроса и независимый предел риска. В «СМО» выберите нестационарную модель с обратной связью или совместную оптимизацию. Экономические потери обслуживания задаются отдельно от базового порога эскалации. Для совместной оптимизации задайте сетку числа операторов, порога, коэффициента связи и ограничения. См. [E2_METHODS.md](E2_METHODS.md) для допущений и интерпретации.

## E2.17–E2.19

В «Чувствительность» выберите «Байес и конформный риск». Задайте априорную массу, отдельную выборку для порога, независимый тест, целевой автоматический риск и уровень PAC. В «Данные» выберите неполную калибровку, настройте EM, загрузите соответствующий JSON либо синтетический пример. Выявление групп в неполном режиме отключено. См. [E2_METHODS.md](E2_METHODS.md) и [E2_ACCEPTANCE.md](E2_ACCEPTANCE.md). Для независимого тестирования из gui: node scripts/check-e2-next.mjs; измерение памяти: node scripts/measure-e2-memory.mjs. Не путать успешный тест с внешним подтверждением безопасности.
