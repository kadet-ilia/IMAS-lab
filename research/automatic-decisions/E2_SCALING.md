# E2.33. Масштабирование хранения и измерения
Старый формат IndexedDB хранил сериализованный массив всех завершенных записей с общим SHA-256; при каждой единице или волне переписывался весь префикс. Новый формат append-v2 использует прежний ключ серии (версия ядра, режим и конфигурация), манифест с числом записей и суммой UTF-8 байтов payload, отдельное хранилище records-v2 с ключом [ключ серии, порядковый индекс]. SHA-256 включает ключ серии, индекс и JSON каждой записи. Это проверка случайного повреждения, не аутентификация от активного противника.
Хеши вычисляются вне IDB транзакции. В одной readwrite транзакции сверяется ожидаемое число записей, вставляются новые записи и изменяется манифест. Вторая вкладка с устаревшим префиксом получает отказ, а не перезаписывает серию. Атомарность означает всю волну или ни одной записи. Отмена вычисления не отменяет уже начатую транзакцию; при восстановлении учитываются только зафиксированные единицы. Восстановление проверяет счетчик, ключи, порядок, хеши, байты и идентичность плана; старый формат мигрирует после проверки общего хеша и плана. При сбое миграции старый формат сохраняется. Очистка удаляет манифест и записи одной транзакцией.
Для равных записей размера S и N единиц при волне W=1 объем сериализуемых полезных данных старого подхода пропорционален S*N*(N+1)/2, нового — S*N. При равных волнах W и N кратном W отношение (N/W+1)/2. Это оценка JSON-полезной нагрузки, не физического дискового ввода-вывода или ускорения всего приложения. В памяти интерфейса по-прежнему находятся все результаты, а восстановление считывает весь массив; графики и экспорт остаются ограничивающими факторами. Лимиты расчетных моделей не увеличены без измерений.

Браузерная проверка: миграция старого контрольного массива из восьми единиц, отклонение поврежденной записи, восстановление идентичного массива; серия 128 конфигураций в четырех потоках. Сравнение фактических байтов новых JSON payload с расчетным объемом переписанных префиксов старого алгоритма; CDP Runtime.getHeapUsage до/после — только моментальные снимки главного renderer, без worker heap и без пикового RSS. Полное время включает вычисления и экспорт. Отдельная независимая проверка E2.35: 128 задач каждого из четырех типов (TV LP, идентификационные границы и LP совместимость, рациональный номинальный POMDP, биномиальный критерий и Холм). Это проверка ограниченных математических постановок, не всех стрессовых режимов.
