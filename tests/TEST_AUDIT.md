## Порядок выполнения

Из корня репозитория:

```bash
cd gui
npm ci
npm test
npm run build
npm run test:hosting:built
npm run preview
```

Отдельно при работающем `npm run preview`:

```bash
cd gui
npm run verify
```

Из корня репозитория для независимых Python-референсов:

```bash
pip install -r requirements.txt
python -m unittest discover -s tests/python -p 'test_*.py' -v
```

В GitHub Actions весь набор запускается из `IMAS_Lab_test`. Описанные
регрессии подтверждают программную согласованность, но **не** завершают
научную приёмку UP-36, внешнюю калибровку или доказательство византийского
консенсуса.

В динамическом физическом пилоте `honestCoverage` характеризует
**наличие** локальной оценки, а `honestLocalControlFraction` —
**фактическое использование** её для команды. Дополнительные

`test_local_plant_reference.py` проверяют невозможность

которого не было в предыдущих тестах. Модули остаются
исключительно в каталоге `tests/`.

## Дополнение 17.11.2026: интервальные гарантии при отказе собственного датчика

Созданы `tests/gui/adaptiveLocalPlantSensorFaults.test.mjs`,
`tests/python/test_local_plant_sensor_fault_reference.py` и
`tests/gui/localPlantSensorFaultReferenceBridge.mjs`.
Система должна явно отказываться от дальнейшего моделирования при
утрате сертификата, даже если истинное состояние ещё находится в
безопасном множестве. Отсутствующее измерение не подменяется
скрытым истинным состоянием либо оценкой с прежней малой
погрешностью датчика. Python воспроизводит переходы интервального
наблюдателя, границы защищённого управления и фактическую динамику
по архиву только выполненных тактов. Контрольная безусловная функция
потерь объявлена до расчёта `R=3` поисковых серий.

**13 модулей Python `unittest`**; дополнительно добавлен
второй специализированный мост для независимого расчёта динамики
и переходов при пропавших измерениях.
